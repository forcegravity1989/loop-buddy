# 规格即测试 (spec-to-tests)

## 何时用

构建段从 SPEC 落到实现之前(先翻译验收标准,再写代码);以及评审阶段
逐条核对验收标准时。

## 步骤

1. SPEC 里每条验收标准编号(AC-1, AC-2, …);写实现前先把它翻译成测试名(如 `ac1_reports_dead_relative_link`)。
2. 无法翻译成测试的验收标准是坏标准——回头改写它,而不是跳过。
3. 实现只做到让测试通过为止,不做规格外功能。
4. 提交前 `cargo test` 全绿是硬门禁;失败输出原样留档,不美化。

## 反例

「系统应当足够健壮」——翻译不成任何测试名,说明它不是验收标准而是感想,
回去改写成可判定的那一条。
