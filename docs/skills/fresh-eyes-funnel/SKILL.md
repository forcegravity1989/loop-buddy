# 新用户漏斗走查 (fresh-eyes-funnel)

## 何时用

运营推广段诊断「发现 → 安装 → 首次使用 → 再次使用」漏斗时;以及上线
改动后做前后对照验证时。

## 步骤

1. 以从未见过本项目的人的视角,真实执行漏斗每一步,不跳步、不脑补。
2. 只记录你真实遇到的摩擦(命令报错、文档缺失、参数不明),不臆想用户。
3. 一次实验只改一个变量,改动前后用同一条真实命令对照。
4. 没有真实流量就如实做「前后对照」,不假装有 A/B 分流。

## 反例

「新用户大概会觉得 README 不够清楚」——你没真走一遍,这是臆想的用户。
去真的跑一次安装,把报错原样贴回来。
