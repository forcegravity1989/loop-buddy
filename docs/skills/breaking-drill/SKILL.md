# 破坏性演练 (breaking-drill)

## 何时用

运维段做事故响应演练、落地健康检查脚本时;以及任何发布前的稳健性检查。

## 步骤

1. 系统性地喂坏输入:不存在的路径、空输入、超长输入、坏参数、坏编码——逐个真实执行并原样记录行为。
2. 任何 panic 或不知所云的报错都算事故:当场修复成友好报错,修后重测。
3. 健康检查脚本必须一键可跑、任何失败以非零码退出;写完真实执行一遍留档。
4. 复盘只引用真实存在的文件与提交号(写之前 ls / git log 核实)。

## 反例

「边界情况应该没问题」——没喂过坏输入就没有结论。真喂一遍,
panic 当场修。
