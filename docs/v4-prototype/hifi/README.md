# V4 MVP 高保真可点击原型 · 简报 v4(样例 = buddy 自己的仓;按 2026-08-19 内部专家评审反馈改)

> **30 秒导读**:这份简报是 [index.html](index.html)(单文件、浏览器直接打开、可点击的高保真原型)的规格,也是后面「详细设计」的骨架。三条总原则(v2 起未变):①**目标态,不是演示走场**——界面上不写解释性文案、不摆演示步骤,只在顶栏留一个很小的「演示数据 ✱」标记;②**不推倒 V3**——V3 成熟的组件原样沿用(结构与样式抄录见 [v3-ui-reference.md](v3-ui-reference.md)),新壳只重排;③**信息密度优先、不编号、不留大片空白**。**本版(v4)按专家评审五条反馈改**(见 §0 第三张表):配置屏「开工工具映射」去掉 agent 列、只留类别 / 开工工具 / **workflow**(workflow = SOP 类技能包,自己调度 agent,不再是 v3 那种「agent 表」);计划屏看板加了**拖拽排期**并说清「待办池 / 待办」的区别;总览名片加**项目群**(WeLink,工厂设计,内部 / 外部之分);总览新增**历史运作(回填)**块,给老项目一个「之前干过什么」的入口;通知屏加「合入并完成」一键与项目群同步 chip。样例数据仍是 buddy 自己的仓(GitHub `forcegravity1989/loop-buddy`,2026-W34)。设计依据:[../mvp-blueprint-draft.md](../mvp-blueprint-draft.md)(第四轮,专家反馈已折入)。看不懂的词查 [`../../../CONTEXT.md`](../../../CONTEXT.md)。

## 0 · 反馈 → 决定(三轮,用户 / 专家能对照)

**收尾前两处修正(2026-08-19,不是专家原话,是内部复核补的,按母文档「写仓一律走分支 + MR 并挂活」的规矩修的)**:

1. **待办池卡片不再显示 ⛔阻塞**。真实状态机(`IssueStatus::can_transition_to`)不允许「待办池(Backlog)→阻塞(Blocked)」——只有待办 / 进行中 / 评审中能进阻塞。待办池卡片现在只留两个按钮:▶开工(待办池→进行中,合法)、**排进本周**(按钮版的拖拽,把活排进当前选中周,效果和拖到「待办」列一样)。待办列卡片不变,仍是 ▶开工 / ⛔阻塞。
2. **「发版本」不再一步写成「已发版」**。原来点「确认发版」直接在内存里追加一条发版记录;改成:确认后 buddy 建一张轻量活「发版本 v0.x」(不起 agent 会话)+ 一个 MR(`docs/releases.md` 追加一行、可选打 tag),活先停在**评审中**;通知屏出现「发版本 v0.x 待合入」一行,和其它待处理活一样有「打开 / 合入 / 合入并完成」三个按钮,有权限时点「合入并完成」才真正算发版。**总览「在研版本与发版记录」只在这一步走完之后才多一行**——发版本弹窗里也加了这句说明,不再是点了就当场发出去。

## 2 · 逐屏

### 2.1 项目墙(`#/wall`)——同 v3,未改

V3 原样:「我的项目」;「本机环境」条(claude · codehub-cli · Open Design + 「测一下」;失败项带「怎么处理 →」);「健康概览」条;两列 ProjectCard 网格。右上「+ 接入项目」。右侧「指南」抽屉(默认收起,四章:环境准备 / 接入项目 / 一周一圈 / 常见问题)。

### 2.2 接入项目(`#/onboard`,两卡)——不加字段(专家反馈:群回头在名片补)

- 卡一「项目地址」:页签 **新建 | 已有**。没有分支、没有本机目录。卡底探活三区。
- 卡二「基础信息」:项目名称 · 你想做什么 · 最像的对标 · 三个月长成什么样(北极星)。
- 「完成接入」→ `#/p/new/overview`(灰总览 + 顶部细横幅「本周还没有计划 · 开始本周」);buddy 自动建运作活③「规范铺底」,**描述按接入方式分两种**(v4 新增):
  - 「已有」仓 → 三步:①写核心件 → ②合并调整(检测到已有 README / CLAUDE.md / AGENTS.md)→ ③历史回填(检测到提交 / 标签 / 远端 issue),三步同一个 MR。
  - 「新建」空仓 → 只有第一步(写核心件),如实注明「无历史可回填」。

### 2.3 总览(`#/p/buddy/overview`,一列横块,自上而下)

1. **项目信息**:左 = 名(衬线)· 一句话 · 对标 · 北极星一句 · **项目群**(v4 新增:未配 → 「未配 · 配置」按钮打开小弹窗——提供方 WeLink · 内部 / 外部 · 待定(灰、不可选,注「工厂留位」)、群号输入、同步哪些通知三个勾;配了 → 「WeLink · 群 &lt;群号&gt; · 通知同步中」+「改」)· 仓 / 负责人 / 规范 v4.0 · 「编辑」;**右 = health 面板**(大灯 + 状态词 + 三条理由全部可见)。
2. **北极星**(单张宽卡)。
3. **滞后指标**(N 张横排)。
4. **引领指标**(N 张横排)。
5. **项目指标 · 代码仓级**(不点灯)。
6. **本周计划进度**。
7. **在研版本与发版记录**(每行只在对应的「发版本」活**合入并完成**之后才出现,见 §2.4)。
8. **历史运作(回填)**(v4 新增,**只有老项目才有**,新接入的空仓不显示):首次提交、累计提交、合入的 PR、远端 issue、git 作者数(含机器人)、近九周合入 PR 数(一排小柱)、版本时间线;每个数字带「回填自 git / GitHub / docs/releases.md」小徽记;块顶一句「回填只解释历史,不算战绩、不点灯;灯从接入那天起只看真实观测。」

### 2.4 计划(`#/p/buddy/plan/<周|all>`,V3 看板 + 周维度合一 + 拖拽排期)

- 左栏(窄):周列表 2026-W34(本周)· W33 · W32 · W31 · **全部**;在研版本下拉。
- 中栏顶部「周头」(选中周时):周目标一句 · 进度条 · 运作活①②③ chip · 按钮 新建活 · 发版本 · 「预览 · 未合入」开关。选「全部」时换成筛选条。
- 中栏主体:**V3 六列看板**:待办池 → 待办 → 进行中 → 评审中 → 已完成 → 阻塞;**列头下一行小字定义**(v4 新增)——待办池「未排进任何一周」/ 待办「已排进本周,等开工」/ 进行中「agent 在干」/ 评审中「MR 开着,等人审」/ 已完成「人点过完成」/ 阻塞「填了原因」。卡片 = V3 结构。运作活①②③也在看板里。**待办池卡片只有 ▶开工 / 排进本周两个按钮,没有 ⛔阻塞**(状态机不允许待办池直接进阻塞);待办列卡片是 ▶开工 / ⛔阻塞。
- **拖拽(v4 新增,专家反馈)**:待办池、待办两列的卡片 `draggable`。待办池 → 待办 = 排进当前选中的周(选「全部」时排进本周),toast「已排进 2026-Wxx」;待办 → 待办池 = 移出周(清空 `week_of`);两列内可拖动排先后(顺序存 localStorage,按项目按列各一个数组)。拖动中,可放的列(待办池 / 待办)高亮;进行中 / 评审中 / 已完成 / 阻塞四列显示「不可放」样式,松手时 toast「状态流转用卡片上的按钮(▶开工 / ⬇合入 / ✓完成 / ⛔阻塞)」——**不改状态**。卡片上的按钮语义照 V3 不变。待办池卡片上的「排进本周」按钮是拖拽的按钮版,效果一样(改 `status`/`week`),给不习惯拖拽的人用。
- **发版本(收尾前改过,不再一步到位)**:点「发版本」打开弹窗(勾选本周已完成的活 + 版本号 + 说明),点「确认 · 建发版活」——**不会**当场写进发版记录,而是新建一张 `kind:'release'` 的轻量活「发版本 v0.x」(不起 agent 会话、没有 ▶开工/续聊 入口)+ 一个 MR,活直接落在**评审中**列。通知屏会出现「发版本 v0.x 待合入」一行(打开 / 合入 / 合入并完成三个按钮,同其它待处理活);点「合入并完成」才会真正把这条发版记录写进总览「在研版本与发版记录」。
- 右侧详情面板(点卡标题滑出,360px):标题、说明、类别、工具、**workflow / 技能**(v4 改名,原「技能 / agent」)、推动指标、MR、来源、`week_of`、`version`、「去会话 →」、「蒸馏」。

### 2.5 会话(`#/p/buddy/session/<会话id>`)——同 v3(Orca 式三栏),终端 sys 行改「workflow 已注入」

左列会话按目录 / worktree 分组;中栏标签页(终端 / 文件只读视图 / diff / Open Design);右栏文件树 + 改动文件 + git 状态 + MR 卡;顶部动作条 ▶开工 / ■停止 / 推到评审 / 蒸馏。**v4 改动**:终端 transcript 里原来的 `[skill] 技能已注入:更新指标与周计划` 一类系统行,凡是注入的是 SOP 类技能包(workflow),都改成 `[workflow] workflow 已注入:<名称>(自己调度 agent)`;活如果还挂了单个技能(如 grillme、systematic-debugging),再补一行 `[skill] 技能已注入:<名称>`。`agent>` 提示符本身不变——那是会话里干活的模型,不是名单。

### 2.6 通知(`#/p/buddy/notify`,左栏入口,未读徽章)

- 上段「待处理」:评审中待合入的行现在有三个动作——打开 · 合入 · **合入并完成**(v4 新增,专家反馈「保持易用性」;有权限时两下合一下,仍是人显式点,toast 说明);已合入待点完成的行保留「点完成」。**项目群同步 chip**(v4 新增):配了群且对应开关打开时,评审中 / 已合入行右侧出现「已发到群 ✓」;未配时,页面顶部一条淡提示「配了项目群,这些通知能直达群 → 配置」,点击跳配置屏。
- 下段「事件」(时间倒序):agent 等你输入 · 运作活②已自动建并开工 · MR 检查通过 · 蒸馏完成 · 指标采集完成 · **已同步到项目群:&lt;活&gt; 进入评审中**(v4 新增,配了群才会出现)。
- 徽章 = 待处理数;项目墙卡片 ⚑ 数同步。

### 2.7 配置(`#/p/buddy/config`,单页四段,v4 结构大改)
