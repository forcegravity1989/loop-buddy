# V4 高保真原型 · 逐屏简报

> **30 秒导读**:这份简报说明 [index.html](index.html)(单文件、浏览器直接打开、可点击的高保真原型)每一屏是什么、样例数据从哪来。**给谁看**:要改 V4 界面的人。**现在还作数吗**:作数,而且它是**视觉正本**——桌面壳 `crates/app-shell/assets/hifi.css` 那张样式表就是从 `index.html` 整体搬过去的,九个屏也是照它重排的(重排的完成记录见 [`../design/13-shell-hifi-gap.md`](../design/13-shell-hifi-gap.md),那里也列了**几处真壳故意没照抄**的地方——原型是演示,真壳没有的东西不假装有)。三条总原则:①**目标态,不是演示走场**——界面上不写解释性文案,只在顶栏留一个很小的「演示数据 ✱」标记(✱ = 假设值);②**不推倒 V3**,成熟组件原样沿用,新壳只重排;③信息密度优先,不编号、不留大片空白。样例数据是 buddy 自己的仓(GitHub `forcegravity1989/loop-buddy`,2026-W34)。看不懂的词查 [`../../../CONTEXT.md`](../../../CONTEXT.md)。

## 0 · 这个原型是怎么定成这样的

原型改过五版,每版都是用户或内部专家看完给的反馈。**那五轮「反馈 → 决定」的对照表已经归档**(见 [`../../archive/v4-prototype/`](../../archive/v4-prototype/) 的握手清单与评审一页纸),决定本身的正本是母文档 [`../mvp-blueprint-draft.md`](../mvp-blueprint-draft.md) §11 的「待拍-NN」台账 —— 想知道某一屏为什么长这样,查那张表,别在这里找。这里只写**今天的样子**。

- 桌面窗口 1440×900 起,1100 宽仍可用;token / 卡片 / chip / 按钮 / 输入框照 v3-ui-reference.md。

## 2 · 逐屏

### 2.1 项目墙(`#/wall`)——同 v3,未改

V3 原样:「我的项目」;「本机环境」条(claude · codehub-cli · Open Design + 「测一下」;失败项带「怎么处理 →」);「健康概览」条;两列 ProjectCard 网格。右上「+ 接入项目」。右侧「指南」抽屉(默认收起,四章:环境准备 / 接入项目 / 一周一圈 / 常见问题)。

### 2.2 接入项目(`#/onboard`,两卡)——不加字段(专家反馈:群回头在名片补)

- 卡一「项目地址」:页签 **新建 | 已有**。没有分支、没有本机目录。卡底探活三区。
- 卡二「基础信息」:项目名称 · 你想做什么 · 最像的对标 · 三个月长成什么样(北极星)。
- 「完成接入」→ `#/p/new/overview`(灰总览 + 顶部细横幅「本周还没有计划 · 开始本周」);buddy 自动建运作活③「规范铺底」,**描述按接入方式分两种**(v4 新增):
  - 「已有」仓 → 三步:①写核心件 → ②合并调整(检测到已有 README / CLAUDE.md / AGENTS.md)→ ③历史回填(检测到提交 / 标签 / 远端 issue),三步同一个 MR。
  - 「新建」空仓 → 只有第一步(写核心件),如实注明「无历史可回填」。

### 2.3 总览(`#/p/buddy/overview`,一列横块,自上而下)

1. **项目信息**:左 = 名(衬线)· 一句话 · 对标 · 北极星一句 · **项目群**(v4 新增:未配 → 「未配 · 配置」按钮打开小弹窗——提供方 WeLink · 内部 / 外部 · 待定(灰、不可选,注「工厂留位」)、群号输入、同步哪些通知三个勾;配了 → 「WeLink · 群 &lt;群号&gt; · 通知同步中」+「改」)· 仓 / 负责人 / 规范 v4.0 · 「编辑」;**右 = health 面板**(大灯 + 状态词 + 三条理由全部可见)。
2. **北极星**(单张宽卡)。
3. **滞后指标**(N 张横排)。
4. **引领指标**(N 张横排)。
5. **项目指标 · 代码仓级**(不点灯)。
6. **本周计划进度**。
7. **在研版本与发版记录**(每行只在对应的「发版本」活**合入并完成**之后才出现,见 §2.4)。
8. ~~历史运作(回填)~~ **v6 删除**(用户:「总览下面怎么多了个历史运作回填?如果是这种增量多了一坨方式,那么我宁愿不回填」)。老项目的历史现在**不另开块**——回填产出的是**同格式**的历史周计划文件(`docs/plan/YYYY-Www.md`,front matter `origin: backfill`)与 `docs/releases.md` 里的历史版本行,于是:历史版本混在第 7 块「在研版本与发版记录」里(带一个灰色小「回填」徽记)、历史周混在计划屏左栏的周列表里(同样带徽记)、历史周文件在知识库文档树里直接能打开。总览 / 计划的 UI 不为回填做任何特殊处理,它们本来就是对着仓里的资产渲染。

### 2.4 计划(`#/p/buddy/plan/<周|all>`,V3 看板 + 周维度合一 + 拖拽统一)

- 左栏(窄):周列表 2026-W34(本周)· W33 · W32 · W31 · **全部**;在研版本下拉。
- 中栏顶部「周头」(选中周时):周目标一句 · 进度条 · 运作活①②③ chip · 按钮 新建活 · 发版本 · 「预览 · 未合入」开关。选「全部」时换成筛选条。
- 中栏主体:**V3 六列看板**:待办池 → 待办 → 进行中 → 评审中 → 已完成 → 阻塞;**列头下一行小字定义**——待办池「未排进任何一周」/ 待办「已排进本周,等开工」/ 进行中「agent 在干」/ 评审中「MR 开着,等人审」/ 已完成「人点过完成」/ 阻塞「填了原因」。**卡面清爽(v5,用户用户拍板)**:卡片上不再摆任何按钮,只留类别 chip、一个可选的第二 chip(「运作」/「自动」/「待确认」)、右上角状态小点;点标题开右侧详情面板,原来那一组按钮(▶开工 / ⛔阻塞 / ⬇合入 / ✓完成 / 排进本周,含新增的「合入并完成」)原样搬进详情面板,当键盘 / 替代路径。
- **拖拽统一(v5,用户用户拍板;v4「只拖排期」的做法已作废)**:**六列全部 `draggable`**,拖到哪列就是哪个动作——待办池 ⇄ 待办 = 排进 / 移出本周(直接生效,toast「已排进 2026-Wxx」/「已移出本周,回到待办池」);拖到**进行中** = ▶开工(弹窗确认:活标题 / 开工工具 / workflow,按钮「开工」/「取消」,确认才真起会话);拖到**评审中** = 推到评审中(弹窗确认);拖到**已完成** = ✓完成(弹窗确认,文案提醒「完成永远由人点——这一下就是」;只收从评审中拖入,若 MR 还没合入则确认后自动先合入再完成);拖到**阻塞** = ⛔阻塞(弹窗填原因,必填,不填不让确认);列内拖动排序照旧(顺序存 localStorage,按项目按列各一个数组,六列都有)。**不合法的转移**(六列对真实状态机 `IssueStatus::can_transition_to` 的镜像——待办池只能到待办 / 进行中,待办只能到进行中 / 待办池 / 阻塞,进行中只能到评审中 / 待办 / 阻塞,评审中只能到已完成 / 进行中 / 阻塞,阻塞与已完成只能回到待办 / 进行中)松手即弹回原位 + toast「X → Y 不允许:原因」(如「待办池 → 已完成 不允许:待办池不能直接完成,要先经过评审中」)。
- **发版本(收尾前改过,不再一步到位)**:点「发版本」打开弹窗(勾选本周已完成的活 + 版本号 + 说明),点「确认 · 建发版活」——**不会**当场写进发版记录,而是新建一张 `kind:'release'` 的轻量活「发版本 v0.x」(不起 agent 会话、没有 ▶开工/续聊 入口)+ 一个 MR,活直接落在**评审中**列。通知屏会出现「发版本 v0.x 待合入」一行(打开 / 合入 / 合入并完成三个按钮,同其它待处理活);点「合入并完成」才会真正把这条发版记录写进总览「在研版本与发版记录」。
- 右侧详情面板(点卡标题滑出,360px):标题、说明、类别、工具、**workflow / 技能**(v4 改名,原「技能 / agent」)、推动指标、MR、来源、`week_of`、`version`、「去会话 →」、「蒸馏」。

### 2.5 会话(`#/p/buddy/session/<会话id>`)——同 v3(Orca 式三栏),终端 sys 行改「workflow 已注入」

左列会话按目录 / worktree 分组;中栏标签页(终端 / 文件只读视图 / diff / Open Design);右栏文件树 + 改动文件 + git 状态 + MR 卡;顶部动作条 ▶开工 / ■停止 / 推到评审 / 蒸馏。**v4 改动**:终端 transcript 里原来的 `[skill] 技能已注入:更新指标与周计划` 一类系统行,凡是注入的是 SOP 类技能包(workflow),都改成 `[workflow] workflow 已注入:<名称>(自己调度 agent)`;活如果还挂了单个技能(如 grillme、systematic-debugging),再补一行 `[skill] 技能已注入:<名称>`。`agent>` 提示符本身不变——那是会话里干活的模型,不是名单。

### 2.6 通知(`#/p/buddy/notify`,左栏入口,未读徽章)

- 上段「待处理」:评审中待合入的行现在有三个动作——打开 · 合入 · **合入并完成**(v4 新增,专家反馈「保持易用性」;有权限时两下合一下,仍是人显式点,toast 说明);已合入待点完成的行保留「点完成」。**项目群同步 chip**(v4 新增):配了群且对应开关打开时,评审中 / 已合入行右侧出现「已发到群 ✓」;未配时,页面顶部一条淡提示「配了项目群,这些通知能直达群 → 配置」,点击跳配置屏。
- 下段「事件」(时间倒序):agent 等你输入 · 运作活②已自动建并开工 · MR 检查通过 · 蒸馏完成 · 指标采集完成 · **已同步到项目群:&lt;活&gt; 进入评审中**(v4 新增,配了群才会出现)。
- 徽章 = 待处理数;项目墙卡片 ⚑ 数同步。

### 2.7 配置(`#/p/buddy/config`,单页四段,v4 结构大改)

1. **开工工具映射**(最上,**v4 改成三列**):行 = 类别(原型 / 构建 / 优化 / 运维 / 运营推广 / 运作),列 = 开工工具下拉(Open Design / Claude CLI / Cursor)· **workflow 下拉**(workflow 表里的条目 + 「无」,含导入的)。**没有 agent 列**。运作类那一行 workflow 下拉禁用、只显示当前值 + 小字注「运作活按活自动选对应运作 workflow」。默认:原型 → Open Design → 原型设计 workflow;构建 / 优化 / 运维 → Claude CLI → **mattpocock-skills**(v5,用户用户拍板改的默认;v4 原默认 superpowers 仍在下拉里可换);运营推广 → Claude CLI → 无;运作 → Claude CLI → 更新指标与周计划。右上「保存(写回 `.bw/issue-policy.toml`)」。
2. **workflow(SOP 类技能包)**(v4 新增,替代原「agent 表」):列 = 名称 · 来源(buddy 内置 / 项目导入)· 入口(SKILL.md 路径)· 自带 agent 数 · 用过几次 · 一句话。数据:superpowers、mattpocock-skills、原型设计 workflow、更新指标与周计划、资产盘点(v5 改名,原「资产盘点与微重构」)、规范铺底(含合并调整 · 历史回填)。**「用过几次」如实**:**v5 起改算 mattpocock-skills**(按样例活数据算出真实数字,标 ✱ 因为是演示数据,但计算方式是真实过滤计数,不是硬编——样例活里业务活的默认 workflow 已从 superpowers 换成 mattpocock-skills,见 §3);superpowers 因样例数据里已无业务活挂它,改写「—(无使用记录)」;其余全部写「—(无使用记录)」,不编。右上「导入」(种类只有 workflow / skill,不再有 agent)。
3. **skill(单个技能)**:列 = 名称 · 来源 · 属于哪个包(或独立)· 一句话 · 启用。数据:grillme(独立,可被 superpowers 等调用)、蒸馏(独立,buddy 自建)、research(mattpocock-skills 包内)、systematic-debugging(独立)、E2E 读回(蒸馏技能)。
4. **连接器 + 定时**(小段并排):连接器表 codehub / GitHub 两行照旧;**表下新增「项目群」子块**(v4 新增):提供方(WeLink · 内部 chip / 外部 · 待定 灰 chip)、群号 + 「配置 / 改」按钮、同步哪些通知(评审中 / 已合入 / 发版 三个开关,直接改 `state.chatGroup`,与总览①的弹窗读写同一份数据)、状态(未配 / 已配)。定时任务列表照旧。

## 5 · 怎么开、怎么核

浏览器直接双击 `index.html` 即可(顶栏「重置」回到样例初态);要按路由跳,起一个静态服务再开 `http://127.0.0.1:<port>/index.html`。

每一版改完都做过两道核验,**结论:过**。①**语法**:把 `<script>` 抽到仓外临时目录跑 `node --check`。②**行为**:起静态服务后用浏览器工具派发真实 DOM 事件(`dragstart`/`dragover`/`drop`/`dragend`)与真点按钮,不直接调页面里的 JS 函数——那样才和真人操作一条路。逐条核过的是:六列拖拽都跟手、不合法转移弹回并给出原因、拖到进行中 / 已完成 / 阻塞各自弹对应确认框(阻塞必填原因)、列内拖动只排序不弹窗、卡面不摆按钮、控制台全程无报错。

**样例数字都是从 buddy 自己的仓实测出来的,不是估的**。设计期曾有两组转述来的数字对不上实测(git 作者数、近九周合入 PR 数),一律以实测为准写进原型;如果母文档里还留着旧数字,以这里为准。
