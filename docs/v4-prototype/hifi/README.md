# V4 MVP 高保真可点击原型 · 简报 v3(样例 = buddy 自己的仓;按前两版原型反馈改)

> **30 秒导读**:这份简报是 [index.html](index.html)(单文件、浏览器直接打开、可点击的高保真原型)的规格,也是后面「详细设计」的骨架。三条总原则(v2 起):①**目标态,不是演示走场**——界面上不写解释性文案、不摆演示步骤,只在顶栏留一个很小的「演示数据 ✱」标记;②**不推倒 V3**——V3 成熟的组件原样沿用(结构与样式抄录见 [v3-ui-reference.md](v3-ui-reference.md)),新壳只重排;③**信息密度优先、不编号、不留大片空白**。**v3 按第二版反馈改**:总览改成一列横块、health 一眼可见;计划屏用回 **V3 六列看板**并与周视角合一;左栏加「通知」入口;项目空间改名「知识库」;接入卡一只管项目地址;工作区根目录进设置;配置单页四段、队友改叫 agent;项目墙加「指南」抽屉。样例数据仍是 buddy 自己的仓(GitHub `forcegravity1989/loop-buddy`,2026-W34)。设计依据:[../mvp-blueprint-draft.md](../mvp-blueprint-draft.md)。看不懂的词查 [`../../../CONTEXT.md`](../../../CONTEXT.md)。

## 0 · 反馈 → 决定(两轮,用户能对照)

**第一版反馈(已在 v2 落地)**:目标态不演示 · 顶层只剩项目墙 + 设置(无资产库 / 鱼塘 / 预算)· 项目墙沿用 V3 卡片 · 待办移出总览 · 会话屏按 Orca 重做 · 配置 = 旧 Hub 精简 + 导入 · 项目空间三页签(知识 / 代码图 / 资产)· 仓统计回到总览。

## 2 · 逐屏

### 2.1 项目墙(`#/wall`)

- V3 原样:「我的项目」;「本机环境」条(claude · codehub-cli · Open Design + 「测一下」;**失败项后面带「怎么处理 →」**,点开右侧指南对应章);「健康概览」条;两列 ProjectCard 网格(标签行 = 在研版本 chip + `W34` + `⚑ N` + 灯 + ×;名;一句话;meta「本周目标:…」+「上次交付 08-17」;进度条)。右上「+ 接入项目」。
- **右侧「指南」抽屉**(默认收起,边缘一个窄标签「指南」;展开 320px):四章目录 环境准备 / 接入项目 / 一周一圈 / 常见问题,点章节显示正文(短,目标态文案,不是演示说明);抽屉底部一个灰色「问题上报」图标位(不可点)。

### 2.2 接入项目(`#/onboard`,两卡)

- 卡一「项目地址」:页签 **新建 | 已有**。新建:平台(codehub / GitHub)· 命名空间 · 仓名 · 可见性;已有:平台 · 搜索框 + 仓列表(或粘贴地址)。**没有分支、没有本机目录。** 卡底探活三区(登录态 · claude · Open Design + 「测一下」)。
- 卡二「基础信息」:项目名称(默认仓名)· 你想做什么 · 最像的对标 · 三个月长成什么样(北极星)。
- 「完成接入」→ `#/p/new/overview`(灰总览 + 顶部细横幅「本周还没有计划 · 开始本周」;通知里 1 条 = 运作活③「规范铺底」的 MR)。

### 2.3 总览(`#/p/buddy/overview`,一列横块,自上而下)

1. **项目信息**:左 = 名(衬线)· 一句话 · 对标 · 北极星一句 · 仓 / 负责人 / 规范 v4.0 · 「编辑」;**右 = health 面板**(V3 健康概览的样子):大灯 + 状态词(平稳 / 需要关注 / 阻塞 / 无数据)+ 三条理由**全部可见**(✓/⚠ + 一句 + 数据来源小字)。名片编辑 → 细横幅「修改已提 MR · 待合入 · 预览 | 合入」→ 合入后「点完成」。
2. **北极星**(单张宽卡):名 · 现值 / 目标 · 保鲜期 · 趋势 · 本周推动它的活 chips · 手填徽记。
3. **滞后指标**(N 张横排,V3 BizMetricCard):同上;灰卡诚实。
4. **引领指标**(N 张横排):同上。
5. **项目指标 · 代码仓级**(V3 那块,不点灯):30 天提交 464 · Rust 115 文件 / 60,824 行 · docs 80 篇 · 30 天 PR 7 · 开放 PR 4 · 技能 9(真值)+ 「↻ 立即采集」。
6. **本周计划进度**:W34 目标一句 · 进度条 · 待办 / 进行中 / 评审中 / 完成 计数 · 运作活①②③三个 chip(状态)· 「去计划 →」。
7. **在研版本与发版记录**(最后):在研 `0.4.0-v4` · 0.3.0-v3 两行。

### 2.4 计划(`#/p/buddy/plan/<周|all>`,V3 看板 + 周维度合一)

- 左栏(窄):周列表 2026-W34(本周)· W33 · W32 · W31 · **全部**;在研版本下拉。
- 中栏顶部「周头」(选中周时):周目标一句 · 进度条 · 运作活①②③ chip · 按钮 新建活 · 发版本 · 「预览 · 未合入」开关。选「全部」时换成筛选条(类别 · 版本 · 来源 · 关键字)。
- 中栏主体:**V3 六列看板**:待办池 → 待办 → 进行中 → 评审中 → 已完成 → 阻塞;列名「{label} · {count}」;卡片 = V3 结构(顶行 mono「#编号 · 类别」+ 「运作」/「自动」chip;标题整行不省略;一行操作区按状态互斥:▶ 开工 / ■ 停止 / 续聊 / ⬇ 合入 MR #N / ✓ 点完成 / ⛔ 阻塞);左边框 3px 状态色。运作活①②③也在看板里。
- 右侧详情面板(点卡标题滑出,360px):标题、说明、类别、工具、agent / skill、推动指标、MR、来源、`week_of`、`version`、「去会话 →」、「蒸馏」。
- 发版本弹窗、预览开关同 v2。

### 2.5 会话(`#/p/buddy/session/<会话id>`)——同 v2(Orca 式三栏),只改用词(agent)

左列会话按目录 / worktree 分组(仓根常驻 shell;每个活的 worktree 一个会话,行上活标题 · 分支 · agent 状态 · 时间);中栏标签页(终端 / 文件只读视图 / diff / Open Design);右栏文件树可点开、改动文件 → diff、git 状态、MR 卡;顶部动作条 ▶开工 / ■停止 / 推到评审 / 蒸馏。三套演示 transcript 不变。

### 2.6 通知(`#/p/buddy/notify`,左栏入口,未读徽章)

- 上段「待处理」:PR #102 评审中(打开 · 合入)· 运作活② W33 评审中(打开 · 合入)· 指标「周循环跑通率」「默认件被真实使用次数」无观测(去补)· 名片修改待合入(出现时);合入后变「点完成」;完成后移到下段并标已处理。
- 下段「事件」(时间倒序):agent 等你输入(减负线收尾会话)· 运作活② 已于 08-14 20:00 自动建并开工 · MR #102 检查通过 · 蒸馏完成「E2E 读回」· 指标采集 09:00 完成。每条可点跳转。
- 徽章 = 待处理数;项目墙卡片 ⚑ 数同步。

### 2.7 配置(`#/p/buddy/config`,单页四段)

1. **开工工具映射**(最上):表格,行 = 类别(原型 / 构建 / 优化 / 运维 / 运营推广 / 运作),列 = 工具下拉(Open Design / Claude CLI / Cursor)· agent 下拉 · skill 多选;下拉里包含项目导入的资产;右上「保存(写回 `.bw/issue-policy.toml`)」。
2. **skill**:表(名称 / 来源 buddy 内置 · 项目导入 / 版本 / 用过次数 / 启用开关);右上「导入」(本机目录 · git 仓地址 · 从另一个项目)。数据:superpowers · grillme · 更新指标与周计划 · 资产盘点与微重构 · 规范铺底(以上内置)· E2E 读回(项目导入 / 蒸馏)。
3. **agent**:原型师(Open Design)· 构建师(Claude CLI / Cursor;战绩 12 胜 3 败✱ 只读);「导入」。
4. **连接器 + 定时**(小段并排):GitHub ✓ · codehub 未配置 | 运作活② 周五 20:00 · 指标采集 每日 09:00。

### 2.8 知识库(`#/p/buddy/kb/…`,三页签,同 v2)

顶条 规范 v4.0 · 对账 ✓ · 看差异 / 升级;知识(文档树 + 渲染)/ 代码图(模块依赖 SVG + 大文件榜 + 符号搜索)/ 资产(项目自有与蒸馏 skill、agent、运作 skill、产物登记、仓统计)。

### 2.9 设置(`#/settings`)

**工作区根目录**(默认 `D:\bw-workspaces`;macOS `~/bw-workspaces`;「更改…」)· claude 路径 · Cursor Agent CLI · Open Design · GitHub 登录 ✓ · codehub。没有预算。

## 5 · 生成与核验

sonnet 子代理在 v2 的 `index.html` 上**增量改**(会话屏、知识库、数据对象、终端 transcript 沿用),≤ 450 KB;主会话只做:能打开、控制台无错、路由都在。用户自己点。
