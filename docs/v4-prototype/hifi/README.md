# V4 MVP 高保真可点击原型 · 简报 v6(样例 = buddy 自己的仓;按 2026-08-20 用户第五 / 第六轮反馈改)

> **30 秒导读**:这份简报是 [index.html](index.html)(单文件、浏览器直接打开、可点击的高保真原型)的规格,也是后面「详细设计」的骨架。三条总原则(v2 起未变):①**目标态,不是演示走场**——界面上不写解释性文案、不摆演示步骤,只在顶栏留一个很小的「演示数据 ✱」标记;②**不推倒 V3**——V3 成熟的组件原样沿用(结构与样式抄录见 [v3-ui-reference.md](v3-ui-reference.md)),新壳只重排;③**信息密度优先、不编号、不留大片空白**。**本版(v5)按用户回 [`../design/00-handshake.md`](../design/00-handshake.md) 的第五轮反馈改**(见 §0 第四张表):计划屏看板**拖拽统一**——六列全都能拖,排期(待办池 ⇄ 待办)直接生效,状态动作(开工 / 推评审 / 完成 / 阻塞)拖完弹窗二次确认,不合法转移弹回,卡面不再摆按钮(按钮组原样搬进右侧详情面板当键盘 / 替代路径);配置屏构建 / 优化 / 运维默认 workflow 改成 **mattpocock-skills**(superpowers 仍在下拉里可换);运作活②改名**「资产盘点」**,范围扩到仓内全部资产(不只代码),微重构从「运作活②自己动手」拆成盘点产出的**建议活草稿**,人勾选才建;老项目历史回填定性为「资产盘点」workflow 的**首次模式**。v4 的五条专家评审改动(开工工具映射三列去掉 agent / workflow 表 / 项目群 / 历史回填块 / 通知合入并完成)原样保留,见 §0 第三张表。样例数据仍是 buddy 自己的仓(GitHub `forcegravity1989/loop-buddy`,2026-W34)。设计依据:[../mvp-blueprint-draft.md](../mvp-blueprint-draft.md)(第五轮,专家反馈 + 用户握手清单已折入)。看不懂的词查 [`../../../CONTEXT.md`](../../../CONTEXT.md)。

**收尾前两处修正(2026-08-19,不是专家原话,是内部复核补的,按母文档「写仓一律走分支 + MR 并挂活」的规矩修的;v5 拖拽统一后,第 1 条「待办池卡片不摆 ⛔阻塞按钮」已被「卡面不摆任何按钮」取代,按钮语义仍保留在详情面板,拖拽层面的合法性改由 v5 状态机镜像表统一守住)**:

1. **待办池卡片不再显示 ⛔阻塞**。真实状态机(`IssueStatus::can_transition_to`)不允许「待办池(Backlog)→阻塞(Blocked)」——只有待办 / 进行中 / 评审中能进阻塞。待办池卡片现在只留两个按钮:▶开工(待办池→进行中,合法)、**排进本周**(按钮版的拖拽,把活排进当前选中周,效果和拖到「待办」列一样)。待办列卡片不变,仍是 ▶开工 / ⛔阻塞。

## 2 · 逐屏

### 2.1 项目墙(`#/wall`)——同 v3,未改

V3 原样:「我的项目」;「本机环境」条(claude · codehub-cli · Open Design + 「测一下」;失败项带「怎么处理 →」);「健康概览」条;两列 ProjectCard 网格。右上「+ 接入项目」。右侧「指南」抽屉(默认收起,四章:环境准备 / 接入项目 / 一周一圈 / 常见问题)。

### 2.2 接入项目(`#/onboard`,两卡)——不加字段(专家反馈:群回头在名片补)

- 卡一「项目地址」:页签 **新建 | 已有**。没有分支、没有本机目录。卡底探活三区。
- 卡二「基础信息」:项目名称 · 你想做什么 · 最像的对标 · 三个月长成什么样(北极星)。
- 「完成接入」→ `#/p/new/overview`(灰总览 + 顶部细横幅「本周还没有计划 · 开始本周」);buddy 自动建运作活③「规范铺底」,**描述按接入方式分两种**(v4 新增):
  - 「已有」仓 → 三步:①写核心件 → ②合并调整(检测到已有 README / CLAUDE.md / AGENTS.md)→ ③历史回填(检测到提交 / 标签 / 远端 issue),三步同一个 MR。
  - 「新建」空仓 → 只有第一步(写核心件),如实注明「无历史可回填」。

### 2.3 总览(`#/p/buddy/overview`,一列横块,自上而下)

1. **项目信息**:左 = 名(衬线)· 一句话 · 对标 · 北极星一句 · **项目群**(v4 新增:未配 → 「未配 · 配置」按钮打开小弹窗——提供方 WeLink · 内部 / 外部 · 待定(灰、不可选,注「工厂留位」)、群号输入、同步哪些通知三个勾;配了 → 「WeLink · 群 &lt;群号&gt; · 通知同步中」+「改」)· 仓 / 负责人 / 规范 v4.0 · 「编辑」;**右 = health 面板**(大灯 + 状态词 + 三条理由全部可见)。
2. **北极星**(单张宽卡)。
3. **滞后指标**(N 张横排)。
4. **引领指标**(N 张横排)。
5. **项目指标 · 代码仓级**(不点灯)。
6. **本周计划进度**。
7. **在研版本与发版记录**(每行只在对应的「发版本」活**合入并完成**之后才出现,见 §2.4)。
8. ~~历史运作(回填)~~ **v6 删除**(用户第六轮:「总览下面怎么多了个历史运作回填?如果是这种增量多了一坨方式,那么我宁愿不回填」)。老项目的历史现在**不另开块**——回填产出的是**同格式**的历史周计划文件(`docs/plan/YYYY-Www.md`,front matter `origin: backfill`)与 `docs/releases.md` 里的历史版本行,于是:历史版本混在第 7 块「在研版本与发版记录」里(带一个灰色小「回填」徽记)、历史周混在计划屏左栏的周列表里(同样带徽记)、历史周文件在知识库文档树里直接能打开。总览 / 计划的 UI 不为回填做任何特殊处理,它们本来就是对着仓里的资产渲染。

### 2.4 计划(`#/p/buddy/plan/<周|all>`,V3 看板 + 周维度合一 + 拖拽统一)

- 左栏(窄):周列表 2026-W34(本周)· W33 · W32 · W31 · **全部**;在研版本下拉。
