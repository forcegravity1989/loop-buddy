# 13 · 桌面壳 vs 高保真:逐屏缺口表

> **30 秒导读**:这是什么——把 `docs/v4-prototype/hifi/index.html`(我们对过的高保真)
> 和 `crates/app-shell/`(已经写出来的桌面壳)逐屏对了一遍,列出**差了什么**。
> 给谁看——接着施工的会话,以及要核对进度的人。现在还作数吗——作数,是当前
> 待施工清单;每做完一屏就在对应小节头上标「已对齐」。

## 结论

V4 的**行为层**(`crates/bw-v4`:四张表、仓当正本、现算推导、内嵌终端、知识库、
群通知)照设计做了,读回验过。**界面层没有照高保真做**:桌面壳只继承了高保真的
配色与字体常量(`theme.rs` 里 13 个色号 + 6 个样式函数 + 12 行全局样式),
其余每一处版式都是照 `design/` 的文字描述现写的行内样式。高保真那 426 行样式表、
216 个类名,一个都没搬。

这违反了高保真自己写在 `hifi/README.md` 里的第二条原则(不推倒 V3,新壳只重排)。
后果不止是「长得不像」——高保真上有的一批功能位,壳里根本没有渲染,ViewModel 也
没有产出对应字段。下面逐屏列。

## 0 · 怎么读这张表

每屏三栏:**高保真有**、**壳里有没有**、**要做什么**。第三栏里:

- **搬版式** = 功能位在,只是排布/样式不对,按高保真重排即可。
- **补渲染** = ViewModel 有数据,界面没画出来。
- **补数据** = ViewModel 也没这个字段,内核那边要先算出来。
- **留位** = 高保真上是明确标注的占位(工厂留位、演示数据),壳里照实做成灰态,
  不假装能用。

## 3 · 总览

高保真是**七块竖排**;壳里是五块,而且第一块把名片和健康并成了上下,不是左右两栏。

| 高保真的块 | 壳里有没有 | 要做什么 |
|---|---|---|
| ① 「本周还没有计划 / 开始本周」横幅(独立一条,置顶) | 混在「本周」块里 | 搬版式 |
| ② 名片 + 健康**并排两栏**(左 1.7 / 右 1,中间竖分隔) | 上下两块 | 搬版式 |
| ② 名片**内联编辑**:想做什么 / 对标 / 北极星 三个输入 + 取消 / 保存 | 无(只有只读展示) | 补渲染 + 补数据(编辑草稿) |
| ② 名片改动的 MR 横幅:待合入(预览 / 合入)→ 已合入(点完成) | 无 | 补渲染 + 补数据 |
| ② 名片元信息行:仓 / 负责人 / 规范版本 / 右侧「编辑」 | 有仓、版本、规范版本,无负责人、无编辑 | 补渲染 |
| ② 名片「项目群」行:未配→「配置」按钮;已配→群号 + 「改」 | 只显示一个字符串 | 补渲染 |
| ② 健康理由行**可点跳转**到对应块 | 只读列表 | 补渲染 |
| ③ 北极星单独一块(左侧 4px clay 竖条,大号数字) | 和滞后/引领挤在同一块里 | 搬版式 |
| ④ 滞后性指标单独一块(横排卡) | 同上 | 搬版式 |

| ⑥ **项目指标 · 代码仓级**:11 项自适应网格 + 「回填自 git / GitHub」徽记 + 「↻ 立即采集」 | **整块没有**(数据只在知识库的资产页签里) | 补渲染(数据已有,挪一份到总览) |
| ⑦ 本周计划进度:四色分段进度条 + 待办/进行中/评审中/完成 四个计数 | 只有一句「排了 N 张活,完成 M 张」 | 补渲染 |

## 9 · ViewModel 要补的字段(汇总)

内核这边要先算出来,界面才画得出:

- 项目级:`signal`(项目轨灯点)、`unread`(通知未读数)、`last_delivery`(上次交付)、`version`
- 指标卡:`target` / `target_assumed` / `manual` / `freshness` / `obs_note` / `week_target` / `achieved`
- 总览:`repo_stats`(代码仓级指标,现在只在资产页签)、`ops_chips`(运作活)、名片编辑草稿与 MR 状态
- 计划:周进度四段计数、看板列定义文案、活卡的 workflow/技能/推动指标/来源、历史周合入 MR 数
- 配置:`workflows`、`connectors`、`crons`;技能补 `enabled` / `pkg` / `desc` / `source`
- 知识库:规范对账结果、符号搜索
- 通知:事件流、指标待补项

## 10 · 施工顺序

1. **样式表整体搬**:高保真 426 行样式表进 `theme::GLOBAL_CSS`,类名照搬;
   行内样式退役。这一步不改任何功能,但后面每一屏都靠它。
2. **外壳骨架**:图标轨 + 项目轨 + 顶栏 + 指南抽屉 + toast + 统一模态框壳。
   做完这一步,人就能在一个对的框子里点。
3. **六屏逐屏重排**,顺序按人最常看的走:总览 → 计划 → 会话 → 通知 → 配置 → 知识库。
   每屏一个提交,先搬版式与补渲染(不动内核),再补数据。
4. **顶层三屏**:项目墙 → 接入 → 设置。

补数据那一档里,凡是今天内核真拿不到的(远端仓列表、符号影响面、群同步回执),
一律做成明确的灰态留位,不放模拟数据 —— 这条不因为「高保真上有」而松动。
