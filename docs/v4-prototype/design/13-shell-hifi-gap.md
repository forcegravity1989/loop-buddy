## 1 · 当初为什么要有这张表

V4 的行为层(`crates/bw-v4`:四张表、仓当正本、现算推导、内嵌终端、知识库、
群通知)照设计做了,读回验过。**界面层当时没有照高保真做**:桌面壳只继承了配色
与字体常量,其余每一处版式都是照 `design/` 的文字描述现写的行内样式,高保真那
426 行样式表、216 个类名一个都没搬。

这违反了高保真自己写在 `hifi/README.md` 里的第二条原则(不推倒 V3,新壳只重排)。
后果不止是「长得不像」:高保真上有一批功能位,壳里根本没渲染,ViewModel 也没有
对应字段——**不同步高保真,功能就会被开发丢掉**。

## 2 · 做完了什么

样式表整体搬进 `crates/app-shell/assets/hifi.css`(只改两处,见那个文件的头注),
行内样式函数全部退役、`theme.rs` 里那 13 个色号常量和 6 个拼样式的函数已删。
九个屏按「总览 → 计划 → 会话 → 通知 → 配置 → 知识库 → 项目墙 → 接入 → 设置」
的顺序逐屏重排,每屏一个提交,提交信息里带着当时的读回。

一并补上的、原本壳里根本没有的功能位:

| 屏 | 补上的 |
|---|---|
| 外壳 | 图标轨 / 项目轨(带未读徽记)/ 顶栏 / 指南抽屉 / toast |
| 总览 | 七块竖排、名片内联编辑与改动 MR 横幅、项目指标·代码仓级、本周进度条 |
| 计划 | 「全部活」视图与四个筛选器、看板列定义、右侧详情抽屉 |
| 会话 | 三栏网格、终端落进中栏(而不是压在信息带下面)、终端标题栏 |
| 通知 | 事件流(从四张表现算,没有事件表) |
| 配置 | 四块真表格:映射 / 技能 / 连接器与项目群 / 定时 |
| 知识库 | 顶部规范条(规范版本 + 管账条数)、代码图真体积榜 |
| 项目墙 | 健康概览条、卡片的版本 / 未读 / 本周目标 / 上次交付 / 完成度条 |
| 接入 | 新建·已有页签、codehub·GitHub 平台切换、探活行 |
| 设置 | 描边列表 + 六项真探活 |

**本机环境探活从「四项里两项永远灰」改成了真探**:claude / cursor-agent /
codehub / gh 在 PATH 里当场找,红绿都是真的;gh 只报装没装(登录态要起子进程,
没接就直说)。Open Design 内嵌与 welink-cli 的探活还没实现,一直是灰的。

## 3 · 没照抄高保真的地方(以及为什么)

这几处是**故意不一样**的:高保真是演示,真壳没有那个东西,与其照抄一个假的,
不如如实改掉并在界面上说清楚。

**下面这张表少了一行,那是好事**:原来还有一条「接入屏可点的仓列表:真壳列不出来,
因为要调平台接口」。那句话是错的 —— `bw_engine` 里两个平台的 `list_repos` 早就有、
V3 一直在用,只是没接到 V4 的界面上。试点第一天用户当场指出来,已经接上,现在列的
是真仓。教训:**「没接」和「做不到」是两回事,别把前者写成后者。**

| 高保真上是 | 真壳改成 | 为什么 |
|---|---|---|
| 顶栏「演示数据 ✱ / 重置 / 头像」 | 库文件名 + 「刷新」 | 数据来自本机库和项目仓,没有可重置的演示数据,也没有账号 |
| toast 2.6 秒自动消失 | 点 ✕ 才关 | 这里放的是「铺底失败,原话是……」,自动消失等于把失败藏起来 |
| 设置屏库文件的「更改…」按钮 | 「改它要在启动前设哪个环境变量」 | 进程起来后库连接已经建好,那个按钮真做出来就是哑弹。**工作区根目录不在此列**,它已经是个能改的输入框(试点第一天用户提的) |
| 代码图的 crate 依赖 SVG | 不画,页面上直说 | 那张图照 buddy 自己的仓画死的,换个项目就是假的 |
| 项目卡的 × 删除 | 不放 | 内核没有删除项目这条命令;摆一个按不动的 × 不如不摆 |

按不动的留位(鼠标停上去写明为什么):预览·未合入、蒸馏、在 Cursor 中打开、
符号搜索、问题上报、welink 探活。**一律灰态,不放模拟数据** —— 这条不因为
「高保真上有」而松动。

## 4 · 还差什么

**只认 `docs/LEFTOVERS.md`**。那里按 V4A/V4B/V4C/V4D 分组登记,本篇不再重复列

workflow 与 skill 的导入与启用、蒸馏命令)。

## 5 · 怎么核

不看截图,看这三样:

```bash
BW_DB=<db> BW_OPEN=<项目名> BW_PANEL=overview target/debug/bw-v4-dev
```

stderr 上的 `[BW_VM]` 三行是可对账的读回:活/会话/事件/周/待评审/阻塞/技能数、
本周五段计数(待办·进行中·评审中·完成·阻塞)、最新一条事件的本机时间、
映射/连接器/定时/群/指标/未读。每个数都能用 `sqlite3` 或 `git` 当场对——
例如本周五段对 `SELECT week_of,status,COUNT(*) FROM issue GROUP BY 1,2`,
最新事件时间对 `date -r <unix>`。

知识库那屏另有 `BW_KB_DUMP=1`,把三个页签的数字打进 stderr。
