使用指导 · 概览

一个 Builder + Agent Loop 的项目管理工作台

Builders' Workbench（口语「buddy」）把传统项目管理的 5 角色 10 流程压成「1 个构建者 + AI 执行小队」。人守质量门与验收，活让 agent 干。本使用指导按界面操作的一个个阶段组织——实践推进到哪，就写到哪。

当前阶段实践到、能见到的

纳入项目→ 找指标→ 绑数据→ 总览呈现→ 健康灯亮

四个阶段各对应一屏（纳入/找指标/绑数据/总览），每屏写操作 → 结果 → 看到。后续阶段随实践推进补在后面。

面向谁

Builder / 构建者
端到端 own 项目的单人，全局唯一，专指人类。
边界
不是团队协作/通用看板/审批系统/云服务。AI 执行 = 本机 claude CLI。

四个控制点

01
知道对标谁
北极星唯一，引领指标可控先行。
02
每周在正常演进
可验证增量替代甘特图，真实 telemetry 难造假。
03
agent 干活，人守验收
干完只到 InReview，Done 永远人显式点。
04
目标清晰且难造假
无数据即 Unknown 而非绿色。
两本怎么配合使用指导按操作阶段讲操作与结果；维护指南站在更高 level，按跨阶段共享的机制汇总——一个机制服务于多个阶段（如 connector 既用于纳入又用于采数，技能加载既用于找指标又用于绑数据）。每章顶部用阶段徽标出用到它的阶段，阶段屏末用 linker 指回涉及的机制章。
事实源：plan/07-product-proposition.md、CLAUDE.md。
使用指导 · 前置准备

开工前先装齐这些

buddy 是本机桌面应用，AI 执行靠 shell-out 本机 claude CLI。分「必装」与「开发验证才装」两组，远端仓连接器按项目 provider 选装。

必装

git基础
项目纳入靠 SSH clone。
claude CLIAI 执行
buddy 通过 claude -p 真开工。Windows 下用 BW_CLAUDE_BIN 给全路径（Rust Command 不做 PATHEXT）。
LLM 网关AI 执行
claude 指向 GLM first-party，配在 ~/.claude.json。BW_CLAUDE_MAX_BUDGET_USD 单次封顶。
远端仓连接器（按 provider 选装）按项目
codehub → codehub-cli + token；github → gh；本地 → 无需。

选装仅开发/验证才需要

Rust 工具链 + mingw + sqlite3开发
从源码构建 app-desktop 需要，含 wasm32 target。

环境变量与启动

# 数据库与工作区
BW_DB=/path/to/bw.sqlite
BW_WORKSPACES=/path/to/workspaces

# 深链（直接打开某项目某面板）
BW_OPEN=<项目名> BW_PANEL=<panel>

# AI 执行
BW_CLAUDE_BIN=/full/path/to/claude
BW_CLAUDE_MAX_BUDGET_USD=2.0

# 启动（Windows 别直接跑 target exe，会崩 0xC0000135）
cargo run -p app-desktop
Windows 启动坑务必 cargo run -p app-desktop，别直接跑 target/ 下 exe，会以 0xC0000135 崩溃。
事实源：CLAUDE.md · 常用命令、DEVELOPMENT.md。
使用指导 · 阶段 01

纳入项目

填个名字 + 一句意图，点确认。剩下 buddy 全兜——clone 仓、挂连接器、排定时器、建三张起手 Issue、扫你项目自带的技能和 agent——你只管后面跑那三张活。

操作两个界面

1
项目墙点「新建」，进入创建流
2
填项目地址：选平台（codehub/github）；起点选「新建仓」或「接入已有」；codehub 选区域（绿区/内源/黄区，黄区未登录如实灰）；接入已有从你的仓列表下拉选
3
命名（必填）+ 一句话意图 brief（可不填）+ 对标谁（可不填，竞品分析用）+ 三个月后怎样算成了（可不填，找指标用）
4
点「确认 · 建立项目」——一个按钮，背后连发整链
接入已有仓时下拉只拉得到你登录 token 关联上的项目——gh / codehub-cli 登录态决定可见范围，关联不到的仓选不了，老实灰，不假装搜得到。

背后点确认那一下，buddy 做了啥

对远端代码仓（GitHub/CodeHub）
  • 建一个新仓（或把你选的已有仓接入），顺手开 3 个 Issue（竞品分析 / 找指标 / 绑数据），把本地起的章程提交推上去
对你的机器
  • 把仓 clone 到本地工作区，写进项目章程（开篇 + 完成创建两段）和四份组件标准文件，供之后建 agent/skill/workflow/cron 对照
对 buddy 数据库
  • 落一条项目记录、铺开五阶段、挂 2 个连接器（仓 + 采集脚本）和一条每日定时器、建 3 张起手 Issue、指标先空着等定时器采——没数据不假装绿

细节（具体哪些连接器/定时器/metric、什么条件下建或不建）见维护指南 Hub 全局库 / Issue 与调度 / 指标与健康。

得到什么建完你手上多了啥

  • 项目在墙，连接状态 green（远端仓接上了）
  • 连接器 + 每日定时器就位——以后每天自动采一次你代码仓的指标（开放 Issue 数 / 已合入 MR 数），指标卡先 Unknown 灰，采到才有值
  • 扫到你项目自带的 skill / agent 等资产，登记进全局 Hub，之后干活能注入
  • 3 张起手 Issue（竞品分析 → 找指标 → 绑数据）在 Backlog，远端 Issues 也同步开了——下一步实践直接开跑
两个已知坑① 点「确认」后 UI 可能冻一会儿：clone 在后台跑（已知 bug，未解），等它跑完即恢复。② 三件套里「竞品分析」别点真跑：联网墙未解，点了会失败；其余两件套可跑通。

建仓 / 连接器 / 定时器 / 三件套这些机制的开发维护口径 → Hub 全局库 + Issue 与调度。

事实源：docs/v1-prototype/issue1-onboard-simplify.md、crates/app-desktop/src/screens/create.rs（Repo→Intent 两卡）、crates/bw-app/src/lib.rs（CreateProject / CompleteCreation）。
使用指导 · 阶段 02

找指标

点 ▶跑 唤醒交互式 claude 会话(灌 north-star skill + 衔接层 system prompt),你和 claude 多轮推导北极星,产出指标定义写进项目仓。

操作

1
运营屏 Issue 看板 →「找指标」卡点 ▶跑(交互)
2
工作流面板嵌终端开 claude——已灌 north-star skill(方法论)+ 衔接层 system prompt(项目意图 + buddy 契约 + 铁律)+ --dangerously-skip-permissions
3
多轮:claude 读项目 desc/benchmark/opportunity + 竞品报告 + governance/derive_*.py,问用户/价值,提北极星(自动化免疫检验 challenge),你确认
4
claude 写 .bw/metrics.toml + docs/metrics-rationale.md 到活分支,提 MR

结果系统/项目改了什么

周边(项目仓)
  • 写 .bw/metrics.toml(北极星 + 引领/滞后 + collect_kind=script|manual + collect_query)+ docs/metrics-rationale.md 到活分支
  • agent 提 MR(gh pr create/codehub-cli mr create,禁 gh pr merge)
本机(buddy DB)
  • Issue InProgress(会话活)→ InReview(buddy 查到 issue 分支 bw/issue-N 的 open MR,读回为证)
  • merge 后 buddy 感知 .bw/metrics.toml → upsert metric 行(origin='file')

看到界面呈现

工作流面板
嵌终端里和 claude 多轮对话(会话持久,点 issue 卡可 --resume 续聊);Issue 卡 InReview + PR#。干完只到 InReview,不到 Done——Done 要你 merge。

本阶段涉及的机制:交互式引擎 / resume / InReview 检测 → 执行与证据;衔接层 system prompt / skill 可换 → 技能与 Prompt;metrics.toml / 北极星 → 指标与健康;Issue 状态机 → Issue 与调度。

事实源:docs/skills/north-star-discovery/SKILL.md、bw-engine/src/interactive_cli.rs · build_bridge_system_prompt、设计 docs/v1-prototype/issue2-metrics-interactive-loop.md。
使用指导 · 阶段 03

绑数据

点 ▶跑 唤醒交互式 claude(metrics-binding skill + 衔接层),和 claude 多轮给每条指标搭采集装置:能自动采的按 buddy 规范建脚本/连接器落 .bw/,不能的手填。

操作

1
「绑数据」卡点 ▶跑(交互) → 嵌终端开 claude(读上游 .bw/metrics.toml + rationale 接上下文)
2
多轮,对每条指标定采集:能自动采→写脚本到 .bw/scripts/ + 连接器清单 .bw/connectors.toml + 配 collect_kind='script'+collect_query=字段路径;不能→manual+手填节奏
3
claude 写回 .bw/metrics.toml collect + .bw/connectors.toml + 脚本,提 MR

结果系统/项目改了什么

周边(项目仓)
  • .bw/metrics.toml collect 字段更新(只动 collect_kind/collect_query,不动 name/def/target)+ .bw/connectors.toml + .bw/scripts/*.py
  • agent 提 MR
本机(buddy DB)
  • Issue → InReview(buddy 查到 open MR)
  • merge 后 buddy 感知 .bw/connectors.toml → upsert connector 行(kind=script)+ .bw/metrics.toml → upsert metric 行

看到界面呈现

运营屏 MetricCard
嵌终端多轮搭装置;Issue InReview + PR#;merge 后 cron(每日 CollectMetrics)自动跑 script connector → observation 有值 → 健康灯亮。manual 指标戴「手填」徽,RecordInline 手填。无「↻同步」手动按钮——merge 自动 sync。

本阶段涉及的机制:绑装置规范(.bw/connectors.toml + buddy 感知 sync)→ 指标与健康;衔接层 / skill 可换 → 技能与 Prompt;交互式引擎 → 执行与证据。

事实源:docs/skills/metrics-binding/SKILL.md、docs/connectors-toml-format.md、bw-app/src/lib.rs · sync_connectors_file_for、设计 docs/v1-prototype/issue2-metrics-interactive-loop.md。

架构与铁律

整套产品的工程底座与不可妥协。后续每个机制章都建立在这之上。

用到此机制的阶段：全部

crate 全景

bw-core
领域内核：StageKind / Issue 状态机 / 度量派生链。零 IO 零 UI，wasm32 可编译。
bw-engine
Executor trait + ClaudeCliExecutor + evidence.rs。
bw-store
SQLite（sqlx）：schema.sql + add_column_if_missing；append-only 表。
bw-app
编排大脑：Command/Event 总线，用例与守卫主战场。
ui
纯函数 selector + ViewModel，wasm32 可编译。
app-desktop
真壳（Dioxus 0.7 hard-pin 0.7.9）。app-web 留口不编译。

两个不可妥协钉进类型与 CI

01
UI 无关内核
五个内核 crate 禁依赖 dioxus/tauri/wry，guard 脚本 + wasm32 check 可证。
02
健康永远 derive
Signal 只能经封口 Derived<Signal> 进缓存，store 无 set_signal。

铁律四条

01
管理体系自带
挂仓即自动建三件套与五阶段。
02
活让 agent 干，人守验收
Done 唯一入边 = InReview，永不自动完成。
03
健康难造假
Signal derive-only，无数据即 Unknown。
04
经验复利
蒸馏 → 注入 → uses+1。

SQLite store
过程信息，append-only。project 行、observation 等落此。

维护指南 · 机制 02

Hub 全局库

跨阶段的共享资产层，project_id=NULL。纳入、找指标、绑数据、总览都经它——connector 供纳入与采数，skill 供找指标与绑数据加载。本章是特性组件介绍：章节与使用阶段解耦，但特性用在哪的 example 关联回使用阶段（见 u2 纳入）。

用到此机制的阶段：纳入找指标·绑数据总览

六套件

connector 连接器
对外连接器（codehub-repo / github-repo / claude-cli）+ 业务脚本（script）。纳入时：挂远端的新项目建 2 个（1 仓 + 1 script），绑定本地仓 / 纯本地 mint 建 0 个。采数经它。用在 u2 步骤④。
skill 技能
唯一能 CRUD 的套件。纳入时扫项目仓自带 skill 登记（种A，见下）。
agent 智能体
五角色全局单例（原型师/构建师/优化师/运营推广师/运维师）。
workflow 工作流
五阶段 template + 自建。
cron 定时
定时调业务脚本（cron→script 可选→connector）。mode=CollectMetrics 跑采集。
knowledge 知识
留口未建。

连接三层模型

心智模型（2026-08-04 钉）：cron 调 script，script 可选调 connector；本地工作区探活不是 connector。

connector 对外连接器
三层模型第 1 层。基础实体，提供「探活函数」——知道怎么连某外部系统 + 探一次看通不通。codehub-repo / github-repo / claude-cli 是。第 2 层 = 业务脚本（见下卡 script）；第 3 层 = 定时器（见下卡 cron_task）。本地工作区读取不是 connector（git-repo 已不建）。example：纳入项目时建 codehub-repo connector，建完即探活（见 u2 步骤④）。
事实源：docs/v1-prototype/issue1-onboard-simplify.md §0
script 业务脚本
三层模型第 2 层。干业务活的脚本，可基于 connector（也可不基于，不强绑），被定时器调。两层：buddy 自带（项目代码仓级采集，config={command, output, script}，输出 JSON 供 metric.collect_query 取值）vs 用户业务级（找指标 skill 产出，用户自己来）。example：纳入时建 1 个 script connector 跑 codehub/github 仓统计（仅挂远端项目，见 u2 步骤④）；metric 取值见 指标与健康。
事实源：docs/v1-prototype/issue1-onboard-simplify.md §0
cron_task 定时器
三层模型第 3 层。调度组件，定时调用业务脚本（cron→script，script 可选→connector）。mode=CollectMetrics 跑采集；另有 run_skill / run_prompt / run_stage_playbook。example：纳入时建 1 条 schedule=Daily mode=CollectMetrics cron（仅挂远端项目，见 u2 步骤④）；采数链见 指标与健康。
事实源：crates/bw-store/src/schema.sql（cron_task 表）
本地工作区探活 evidence
从工作区真实状态回流观测（git/docs/测试），不是 connector——本地不是对外连接器。纳入时调（clone 后读状态），但不建模成 connector 行。
事实源：crates/bw-engine/src/evidence.rs
Remote 工厂
provider 分叉（codehub / github）收敛一处。新增 provider 只改工厂。
事实源：CLAUDE.md · 架构

skill 六渠道

skill 渠道
纳入时实践了 种A：项目仓自带 skill 扫进来登记可见，不进任何注入下拉。其余渠道（Boot seed / 手建 / 蒸馏 / 导入单包 / 批量导入）待 技能与 Prompt 章对应窗口棒补。
事实源：crates/bw-app/src/lib.rs（sync_project_assets）
技能注入/蒸馏复利见「技能与 Prompt」章；metric/observation/signal 见「指标与健康」章。

维护指南 · 机制 04

技能与 Prompt 加载

找指标、绑数据都加载系统预制技能（north-star-discovery / metrics-binding）。技能是 buddy 的复利资产。V1 起 skill 方法论可换（业界 skill 也行），buddy 衔接层 system prompt 不可换——包项目上下文 + 契约 + 铁律。

用到此机制的阶段：找指标绑数据

系统预制技能

三件套技能
north-star-discovery（找指标）/ metrics-binding（绑数据）/ competitive-analysis（竞品分析，联网墙未解）。
事实源：docs/skills/
五阶段方法论
baseline-before-touch / breaking-drill / evidence-first / fresh-eyes-funnel / spec-to-tests。
事实源：docs/skills/

交互式 skill 注入（V1）

衔接层 system prompt 不可换
--append-system-prompt 灌项目上下文（PlaybookCtx：desc/benchmark/opportunity/north_star）+ buddy 契约（写 .bw/metrics.toml 按 script|manual 两 kind、读 governance//derive_*.py 优先对齐、产 metrics-rationale.md、绑数据建 script connector 经正规 create_connector）+ 铁律（Done 不自动/settle-once/signal derive-only/Unknown≠绿）。任何 skill 进来都包这层。
事实源：bw-engine/src/interactive_cli.rs · build_bridge_system_prompt
skill 方法论 可换
skill 正文经位置参数 prompt 注入(本机 claude --help 无 --prefill,用位置参数等价 auto-send)。**P4 起 SKILL.md 改纯方法论**(buddy 契约抽到衔接层,不重复)——换业界 skill 当 prompt 注入,产出仍对得上契约。
事实源：bw-engine/src/interactive_cli.rs · build_startup_plan、docs/skills/
声明式 CLI 表
TuiAgentConfig 静态表，claude 支持 / cursor 占位（先不接）。加新 CLI 加一行配置，不是新 impl。
事实源：bw-engine/src/interactive_cli.rs · CLAUDE/CURSOR
权限
交互式 --dangerously-skip-permissions（流体操作不老问）+ --disallowedTools "Bash(gh pr merge)"（守"人 merge"铁律——跳权限询问 ≠ 绕 deny 名单）。后台 one-shot 休眠轨留 acceptEdits。
事实源：bw-engine/src/interactive_cli.rs · build_startup_plan
注入/蒸馏复利链见下;CRUD 在 Hub 全局库。V1 已建:嵌入终端(PTY + xterm + hook→事件,Phase 2b)+ skill 重写(P4,SKILL.md 纯方法论、契约唯一在衔接层)。设计见 docs/v1-prototype/issue2-metrics-interactive-loop.md。

注入与复利

skill 注入
干活时自动把最相关技能带进队友上下文。
