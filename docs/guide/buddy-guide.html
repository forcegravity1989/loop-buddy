使用指导 · 概览

一个 Builder + Agent Loop 的项目管理工作台

Builders' Workbench（口语「buddy」）把传统项目管理的 5 角色 10 流程压成「1 个构建者 + AI 执行小队」。人守质量门与验收，活让 agent 干。本使用指导按界面操作的一个个阶段组织——实践推进到哪，就写到哪。

当前阶段实践到、能见到的

纳入项目→ 找指标→ 绑数据→ 总览呈现→ 健康灯亮

上面是主闭环（纳入→找指标→绑数据→总览→健康灯），四阶段各对应一屏，每屏写操作 → 结果 → 看到。旁路还可随时建活 · 选技能——开自己的活、挂方法；那是旁路，不是主闭环必经五步。

面向谁

Builder / 构建者
端到端 own 项目的单人，全局唯一，专指人类。
边界
不是团队协作/通用看板/审批系统/云服务。AI 执行 = 本机 claude CLI。

四个控制点

01
知道对标谁
北极星唯一，引领指标可控先行。
02
每周在正常演进
可验证增量替代甘特图，真实 telemetry 难造假。
03
agent 干活，人守验收
干完只到 InReview，Done 永远人显式点。
04
目标清晰且难造假
无数据即 Unknown 而非绿色。
两本怎么配合使用指导按操作阶段讲操作与结果；维护指南站在更高 level，按跨阶段共享的机制汇总——一个机制服务于多个阶段（如 connector 既用于纳入又用于采数，技能加载既用于找指标又用于绑数据）。每章顶部用阶段徽标出用到它的阶段，阶段屏末用 linker 指回涉及的机制章。
事实源：plan/07-product-proposition.md、CLAUDE.md。
使用指导 · 前置准备

先跑安装器，再从开始菜单打开

同事装的是第一包：内部用的 Windows 安装器 BuildersWorkbench-Setup.exe。装包前先备齐安装器不管的三样；装完从开始菜单或桌面图标打开。不要把从源码启动当成终端用户的路径。

必装安装器不管，装包前要有

Claude Code
用 npm 全局安装 @anthropic-ai/claude-code，buddy 靠它真开工。安装器会找 %APPDATA%\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe；找不到就中止，不会帮你建目录。
git
纳入项目靠 SSH clone。安装器不装 git。
WebView2 Runtime
系统里已经有这份网页控件运行时即可。安装器不检测、也不替你装；它只把配套的 WebView2Loader.dll 放进程序目录。
先装 Claude Code，再跑安装器找不到那份 claude.exe 时，向导会直接停住。请先全局装好，再双击安装包。

第一包跑安装器（已实践）

1
向出包的同事要 BuildersWorkbench-Setup.exe（内部用，从出包机器拿，不进 loop-buddy 仓），双击跑向导
2
默认装到 D:\BuildersWorkbench，向导里可以改
3
装完从开始菜单或桌面图标打开，不要再把 cargo run -p app-desktop 当成终端用户的启动方式
安装器会替你做
  • 写用户环境变量 BW_CLAUDE_BIN，指向上面那份 claude.exe 全路径
  • 本机已有 codehub-cli 时不覆盖、卸载也不删；没有才拷一份到 %USERPROFILE%\bin
GitHub 仓要另装若仓在 GitHub，需另装 gh。第一包面向内部 Windows + CodeHub，不带 gh。

装完必做结束页写的那几条

向导结束页标题是「装完必做」。按下面做完，再去纳入项目。

1
关掉安装器，从开始菜单重新打开 buddy
2
在终端登录 CodeHub 命令行：
codehub-cli auth login
3
clone 用的 SSH 地址是 szv-open.codehub.huawei.com:2222，和 codehub-cli 登录用的 API 地址不是同一个，别混
4
claude 打到哪台网关，写在本机 ~/.claude.json 里，不是 buddy 里配
5
程序在你向导里选的目录；数据库和工作区在 %APPDATA%\BuildersWorkbench

选装从源码构建时才需要

Rust 工具链 + mingw开发
只有从源码构建桌面壳才需要。开发机命令仍是下面这一条，不是同事装第一包的路径。
cargo run -p app-desktop
开发包不是同事主路径BuildersWorkbench-Dev-Setup 不要写成已经就绪的安装方式。本机拉 Rust 安装程序时曾被安全软件隔离，没有作为同事验收路径。
事实源：iterations/PRACTICE-buddy.md §1 前置、§4.14（第一包已在开发机装过并验过）。安装器在仓外，不进 loop-buddy。
使用指导 · 阶段 01

纳入项目

主推接入已有仓：选平台 → 选仓 → 填名字点确认。buddy 负责 clone、挂连接器、排定时器，并按仓里有没有 .bw/project.toml 区分首到者与后来者——同一项目可被多台 Buddy 分别纳管，共同事实从仓读回。

操作两张卡

1
项目墙点「新建项目」，进入创建流
2
「仓从哪来」：选平台（codehub/github）；起点选「新建仓」或「接入已有仓」；codehub 选区域（绿区/内源/黄区）；接入已有点「↻ 刷新列表」后从下拉选
3
「你想做什么」：项目名称（必填）+ 一句话意图 / 对标谁 / 三个月后怎样算成了（均可空）。后来者（选仓后探测到远端已有 .bw/project.toml）：意图区只读预填正本字段，不必重填；首到者仍手填，确认后写入正本
4
点「确认 · 建立项目」——一个按钮，背后连发整链；进度见上方条，完成后进项目
判据：仓里有 .bw/project.toml = 后来者（读回正本、不建三件套；选仓后意图只读预填）；没有 = 首到者（手填意图、写正本、建三件套）。下拉只列出你当前登录能看到的项目。

背后确认建立后系统执行了什么

对远端代码仓（GitHub/CodeHub）
  • 首到 · 新建仓：创建空仓；开 3 个起手 Issue；把 .bw/project.toml（及章程等）commit 上主干并推送
  • 首到 · 接入已有：clone 后写 .bw/project.toml，走 bw/project-init 分支提 PR 并由 Buddy 自动合入（这是配置落仓，不是自动完成一张活）；失败会 tip，需你手动 merge。然后开 3 个起手 Issue
  • 后来者 · 接入已有：clone 后不再远端开那 3 个 Issue（启动包已由首到者发过）；不写不推 project.toml
对你的机器
  • 把仓 clone 到 buddy 工作区（默认 %APPDATA%\BuildersWorkbench\workspaces\<名>-<短id>）
  • 创建收尾读回仓内正本：.bw/project.toml（若有）+ metrics.toml + connectors.toml → 写入本机 buddy 缓存
对 buddy 数据库
  • 落项目记录、五阶段、仓连接器 + 每日采集定时；首到者再建 3 张起手 Issue 并种仓指标；后来者从仓拉 open Issue 重建本地看板（可 ▶跑；不重开远端）

细节见维护指南 Hub 全局库 / Issue 与调度 / 指标与健康。

得到什么建立完成后的结果

  • 项目在墙——点进运营屏；侧栏能看到扫到的本项目 skill / 定时器 / 连接器
  • 总览 · 项目指标两张仓卡 + 阶段完成一行；有值就显示，没值灰着（Unknown ≠ 绿）
  • 首到者：3 张起手 Issue 在看板待办池；工作区已在默认主干；仓里有意图正本 .bw/project.toml
  • 后来者：toast「正本已读回」+「从仓同步 Issue」；不重复建三件套远端；本地看板出现仓上已有的 open Issue（待办池），可 ▶跑
本机删了再接入同仓
删项目后再「接入已有」同一仓：不新开远端起手 Issue、不重推 project.toml；仍走后来者读回，并把远端 open Issue 重建进本地看板。删项目会清 buddy 库，并删掉 buddy 自建的 workspaces\<名>-<短id> 工作区（你自己绑的已有目录不删）。

竞品分析三件套之一怎么用

起手三件套里的①「竞品分析」需要联网抓取对标产品的公开页面。当前本机 claude 环境暂不支持这类抓取——点了会失败。联网能力就绪后再开跑；现阶段先留着这张活，其余两件套可正常跑通。

想看「连接器 / 定时器 / 三件套 / 正本读回」怎么设计的 → Hub 全局库 + Issue 与调度。

事实源：V2-② Phase A + V2-②-I（仓平台 open Issue 单向读回）——首到：PR 合入 project.toml、本地 3 起手 Issue；后来者删后再接入：不重开远端三件套、不重推正本、读回 open Issue 到本地待办池。IntentUX（选仓后只读预填）已落地。设计：docs/v2-prototype/same-project-multiple-workbenches.md。

使用指导 · 阶段 03

绑数据

一句话：把「打算怎么采」搭成真装置——能自动的写脚本登记连接器，不能自动的保持手填。合入后立刻采一轮，之后不用新建定时器：原来那条每日采集会跑本项目全部脚本。

→

scripts + toml
→

同步进 buddy
→
每日采集

→
出数
总览业务卡有值

操作

1
「绑数据」点 ▶跑(交互)——它会读你已合入的指标计划
2
能自动采的：让模型写脚本并登记到 .bw/connectors.toml；只能手填的：保持计划即可
3
提合并请求 → 看板 ⬇ merge PR（或网页合完再点「已完成」）
4
合入后 buddy 会立刻采一轮；总览应已有数。没有再点「↻ 立即采集」，或等每日定时

看左侧「连接器」：除了仓本身，还应出现你刚绑上的业务脚本。定时任务多半还是原来那一条——这是正常的。

和模型核对这三件事

请确认正确样子不对时你会看到
连接器表头写成 [[connector]]（单数）同步时报错，侧栏多不出新连接器
脚本怎么交结果写到约定的结果文件里只在终端打印 → 总览一直采不到
本机怎么跑脚本用你机器上真有的命令（Windows 常见 py）采集失败、业务卡仍灰
定时器怎么理解
面板上多半仍只有一条「… · 采集代码仓指标」。别被名字骗了——到点会跑本项目每一个采数脚本（仓统计 + 你绑的业务脚本）。文件里写的采集周期不会再多出一条定时任务。

使用指导 · 阶段 04

总览呈现

一句话：每周看这一屏就够——上面是仓的现状数（不点灯），下面是业务健康（点灯）。没采到就灰，不替你假装绿。

一屏怎么读
项目指标
开放 Issue / 已合入 MR… · 不点灯、不上卷业务健康
业务指标
北极星 → 滞后 → 引领 · 有数才可能亮；没数就灰
buddy 情况
待合入、本周未记… · 「完成」只能你点

操作

1
阶段轴点「◎ 全部阶段 · 总览」
2
自上而下扫三层；灰卡 = 还没采到数，或还没绑上采集方式
3
想立刻出数：项目指标区「↻ 立即采集」（与每日定时、创建收尾走同一条采数链）。仓指标（开放 Issue / 已合入 MR）会带近 30 天点，buddy 只补本地还没有的天——存量项目不必重接
4
你在仓里改了指标计划、还没走合并：业务区「↻ 同步指标文件」（只同步计划，不采新数）

上图：上面仓指标已有数；下面北极星 / 周新增仍灰——要么还要手填，要么自动采还没跑成功。没数就灰，不会假装绿。

三个易混概念

你看到的实际意思
「手动 / 脚本」标注这是采集计划，不是「已经有数」
灰卡 / —还没有采到的数值（不是绿灯）；Unknown ≠ 绿
「手填」徽这条数是人手填的；总览卡上暂时还不能直接填
折线 / vs 上周按周聚合近史（仓指标常能看出约 4 周）。业务脚本若没带历史，诚实单点，「vs 上周」可能是「—」——不假装有曲线
折线旁 → 0.0可能是空周沿用了上周，不是「稳住了」——留意「本周未记」
杂项点完成时若提示「登记了 N 个产物」，N 往往接近整仓文件数，不是业务产出件数。删项目会清 buddy 记录 + 自动删 buddy 自建的 clone 工作区；你自己绑的已有目录不删（留着你的证据）。

指标与健康怎么设计的 → 指标与健康

事实源：cowelink 总览；V2-② Phase B——「立即采集」/cron/创建收尾同一条链，仓统计带近 30 天历史、只补缺测天；无历史的业务脚本诚实单点；手填不补历史。约定见 docs/buddy/standards/connectors.md「近 30 天历史」。

建活 · 选技能

一句话：总览看明白缺什么之后，在 Issue 看板最上方一行开一件活——填标题、选阶段、挂一条方法（技能），落进「待办池」。队友在卡片上指派，不在创建行绑。

背后buddy 自动干了啥

  • 对远端代码仓：挂了远端的项目，创建会去远端开一张同名 Issue（网页建的进不来 buddy 看板）
  • 对你的机器：尚未 clone / 写文件——建活只立账，不动磁盘
  • 对 buddy 数据库：落一条 issue 行（状态 待办）、按阶段归位、挂上所选技能

你会得到

  • 一张待办卡，带着阶段和技能信息（选了显式技能或用阶段默认）
  • 点 ▶ 跑 即开工：所有 issue ▶跑 都进嵌入终端（每卡一会话），队友在真实工作目录改文件（见下）
  • 无显式技能也跑：按 issue 所在阶段自动装载默认方法（如构建段用 spec-to-tests）；issue 标题+描述作首句 prompt
易踩① 空标题点创建会被静默忽略（没反馈，不是卡住）——先填标题。② 挂远端时创建要等远端开票回来，无进度条，体感像卡住，稍等。③ 同项目同时只一件活在交付中（串行）；别的卡点「▶ 跑」会显示「排队中」。

▶ 跑 · 嵌终端 · 完成

1
卡片点 ▶ 跑：队友开工，跳到工作流屏的嵌终端（每卡一会话）
2

3

一活一会话每卡独立 PTY

会话生命周期
  • 首次 ▶跑：建 claude_conversation 行 + spawn PTY（占 active_run）
  • 切到别的卡再回来：接回原 PTY（不杀，切显示/键盘）
  • Done/InReview 仍可点「续聊」：咨询态，走 consultation_runs，不占 active_run、不 settle、不改状态
  • buddy 重启后 PTY 全死（如实）；点卡按原路径重建 worktree + --resume，不在启动时批量唤醒
  • 新活靠读已合入产物接上下文（薄编排器）
人怎么驱动 + 焦点同步
  • 点跑 / 续聊 → 嵌终端多轮改仓内文件
  • agent 自提 MR → buddy poll 读回 → InReview
  • 人 merge / 显式完成 → Done（pull + Sync* 装表）
  • 左侧 session 卡 ↔ 嵌终端焦点双向同步：按 #N 标题 匹配 issue，切卡不杀 peer PTY

交付离开 InProgress（→InReview poll / →Done merge）且 PTY 仍活 → 降级为咨询（放锁、handle+guard 迁 consultation_runs、补记 skill uses、不杀 PTY/不清 worktree）。降级 PTY 退出走 cleanup_demoted_consultation 防泄漏。降级 PTY 不带 §6.2 咨询 prompt（下次 resume 才注入，诚实口径）。

可见 vs 不可见别把首条任务当成没注入

V2-① 已落地（cowelink 找指标实跑确认）：嵌终端里用户看得见的自动首段 = 位置 prompt（issue 标题+描述）。buddy 系统提示词 + 项目上下文 + 主 Skill 全文走 claude --append-system-prompt，属 Claude 的系统侧上下文——不会再以用户消息形式打在聊天气泡里。验收方式：会话内追问铁律 / 主 Skill slug；或本机看进程命令行是否带 --append-system-prompt。恢复会话不重灌这层（沿用首次）。

拼装issue 终端会话的 prompt 模型

  • 所有 issue ▶跑 都进嵌入终端（每卡一会话），不再只限找指标/绑数据两技能。
  • 位置 prompt = issue 标题+描述（auto-submit 首句用户消息；描述空则只标题）——唯一默认可见的那段。
  • 系统提示词 = A system-prompt.md + B 项目上下文 + C 主 Skill + D 蒸馏块 + E 目录块（--append-system-prompt），用 --- 分段——对用户默认不可见，但对模型已加载。
  • C 主 Skill 选择规则：显式选的 > 阶段默认 > 无。显式选 = 替换默认（不叠加两份）。无显式选时按 issue 自身阶段取默认 SOP（不随项目交棒改变）。
  • B 项目上下文文案三档：默认方法显「使用本阶段默认方法: <slug>（用户选了自己的技能时替换此默认）」；显式选显「你正在执行技能: <slug>」；无任何技能显「未关联技能」。
  • 五阶段默认 Skill 各带协作 SOP：讲清 Claude 在会话内何时调独立 SubAgent、各角色交接什么产物、何时回用户确认。buddy 不再脚本调度 issue 的 agent。
  • D 蒸馏排除主 Skill：effective_skill（显式或默认）被排除出蒸馏候选,不冒充第二份主 Skill。
  • 阶段循环只用于非 issue 命令：stage playbook / hub workflow / cron 仍用 buddy 脚本调度的阶段循环机器。
  • 恢复不重灌（§7.1）：恢复前更新规范运行副本,然后接回原会话；系统提示词、项目上下文、主 Skill 仍是首次启动版本；界面 toast 提示沿用首次上下文。
  • 规范物化：开工前写入工作区 .claude/buddy/standards/metrics.md（及 connectors），带 .bw-managed，并加入 Git info/exclude（不改用户 .gitignore）。路径须与系统提示词索引一致；半写失败会清掉不完整目录。
  • macOS Unix PTY adapter：未建，留口。V1 交互式 Windows-only。
