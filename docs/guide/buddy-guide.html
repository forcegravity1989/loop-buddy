使用指导 · 概览

一个 Builder + Agent Loop 的项目管理工作台

Builders' Workbench（口语「buddy」）把传统项目管理的 5 角色 10 流程压成「1 个构建者 + AI 执行小队」。人守质量门与验收，活让 agent 干。本使用指导按界面操作的一个个阶段组织——实践推进到哪，就写到哪。

当前阶段实践到、能见到的

纳入项目→ 找指标→ 绑数据→ 总览呈现→ 健康灯亮

四个阶段各对应一屏（纳入/找指标/绑数据/总览），每屏写操作 → 结果 → 看到。后续阶段随实践推进补在后面。

面向谁

Builder / 构建者
端到端 own 项目的单人，全局唯一，专指人类。
边界
不是团队协作/通用看板/审批系统/云服务。AI 执行 = 本机 claude CLI。

四个控制点

01
知道对标谁
北极星唯一，引领指标可控先行。
02
每周在正常演进
可验证增量替代甘特图，真实 telemetry 难造假。
03
agent 干活，人守验收
干完只到 InReview，Done 永远人显式点。
04
目标清晰且难造假
无数据即 Unknown 而非绿色。
两本怎么配合使用指导按操作阶段讲操作与结果；维护指南站在更高 level，按跨阶段共享的机制汇总——一个机制服务于多个阶段（如 connector 既用于纳入又用于采数，技能加载既用于找指标又用于绑数据）。每章顶部用阶段徽标出用到它的阶段，阶段屏末用 linker 指回涉及的机制章。
事实源：plan/07-product-proposition.md、CLAUDE.md。
使用指导 · 前置准备

开工前先装齐这些

buddy 是本机桌面应用，AI 执行靠 shell-out 本机 claude CLI。分「必装」与「开发验证才装」两组，远端仓连接器按项目 provider 选装。

必装

git基础
项目纳入靠 SSH clone。
claude CLIAI 执行
buddy 通过 claude -p 真开工。Windows 下用 BW_CLAUDE_BIN 给全路径（Rust Command 不做 PATHEXT）。
LLM 网关AI 执行
claude 指向 GLM first-party，配在 ~/.claude.json。BW_CLAUDE_MAX_BUDGET_USD 单次封顶。
远端仓连接器（按 provider 选装）按项目
codehub → codehub-cli + token；github → gh；本地 → 无需。

选装仅开发/验证才需要

Rust 工具链 + mingw + sqlite3开发
从源码构建 app-desktop 需要，含 wasm32 target。

环境变量与启动

# 数据库与工作区
BW_DB=/path/to/bw.sqlite
BW_WORKSPACES=/path/to/workspaces

# 深链（直接打开某项目某面板）
BW_OPEN=<项目名> BW_PANEL=<panel>

# AI 执行
BW_CLAUDE_BIN=/full/path/to/claude
BW_CLAUDE_MAX_BUDGET_USD=2.0

# 启动（Windows 别直接跑 target exe，会崩 0xC0000135）
cargo run -p app-desktop
Windows 启动坑务必 cargo run -p app-desktop，别直接跑 target/ 下 exe，会以 0xC0000135 崩溃。
事实源：CLAUDE.md · 常用命令、DEVELOPMENT.md。
使用指导 · 阶段 01

纳入项目

一条 URL 把项目挂进来。砍掉了原 host·path·platform 三段分卡和让人填不准的指标字段。

操作

1
项目墙 → 新建
2
填一条项目地址（codehub / github URL）
3
命名 + brief
4
确认建立

结果系统/项目改了什么

落库与产出
  • 仓库 SSH clone 到 BW_WORKSPACES
  • SQLite 落 project 行
  • 建 2 个 connector（git-repo + provider 适配）
  • 自动建标配 Issue 三件套（竞品分析 / 找指标 / 绑数据）状态 Backlog

看到界面呈现

项目墙
项目出现在墙，连接状态 green；三件套 Issue 已在 Backlog。
竞品分析别点真跑联网墙未解（bug②）。UI 保留入口但标 warn，点了会失败。其余两件套实测可跑通。

本阶段涉及的机制（connector / Remote 工厂 / project 行 / 幂等守卫）→ 见维护指南 Hub 全局库；三件套自动建 → Issue 与调度。

事实源：v1-onboarding-overview.html Tab①、PRACTICE-buddy.md §2。
使用指导 · 阶段 02

找指标

AI 跑 north-star-discovery skill，产出指标定义写进项目仓。

操作

1
三件套看板 → 「找指标」卡
2
指派队友 / 触发 RunIssue
3
AI 跑 north-star-discovery skill
4
review 产出的指标定义

结果系统/项目改了什么

落库与产出
  • 产出 .bw/metrics.toml 写进项目仓（北极星 + 引领/滞后 + 目标值 + 比较符 + 黄区带）
  • Issue 状态 Backlog → InProgress → InReview
  • Run 记录入账（成败 / 耗时）

看到界面呈现

三件套看板
「找指标」卡状态到 InReview；metrics.toml 在仓里可见。干完只到 InReview，不到 Done——Done 要你显式点。

本阶段涉及的机制：RunIssue / Run / Issue 状态机 → Issue 与调度；预制技能 → 技能与 Prompt；Executor / evidence → 执行与证据；metrics.toml / 北极星 → 指标与健康。

事实源：v1-onboarding-overview.html、docs/skills、实测 ~21min。
使用指导 · 阶段 03

绑数据

AI 跑 metrics-binding skill，给每条指标接采集方案。此时指标有定义、有采集方案，但还没采数、还没点亮。

操作

1
review 找指标的产出
2
「绑数据」卡触发 RunIssue
3
AI 跑 metrics-binding skill
4
给每条指标接采集方案

结果系统/项目改了什么

落库与产出
  • 每条指标接采集器类型 + 采集配置
  • 产出登记写进仓
  • Issue → InReview

看到界面呈现

三件套看板
「绑数据」卡 InReview；指标已有采集方案但还没采数、没点亮——点亮要等 merge 后总览呈现阶段。

本阶段涉及的机制：metrics-binding 预制技能 → 技能与 Prompt；采集器 / probe vs collect / manual 带徽 → 指标与健康。

事实源：docs/skills、实测 ~19min。
使用指导 · 阶段 04

总览呈现

merge 指标定义后，采数、重算信号、点亮。项目从纳入走到健康灯亮。

操作

1
merge 指标定义（走 PR）
2
等 cron / connector 采数
3
打开项目总览

结果系统/项目改了什么

落库与产出
  • SyncMetricsFile 把 metrics.toml 装进 metric 表
  • 采集器 collect 写 observation 表（真实数据点，append-only）
  • recompute_signals 重算 Signal
  • 健康灯亮

看到界面呈现

项目总览
纳入卡 / 三件套看板 / 北极星 + L1·L2·L3 / 健康灯（Green / Amber / Red / Unknown）。

健康灯怎么读

Green · 隐身（正常不出声）
Amber · 黄区预警
Red · 越界
Unknown · 无数据
无数据 ≠ 绿色没有观测就是 Unknown（灰），绝不是 green。绿色「隐身」——只有红、黄出声。

本阶段涉及的机制（SyncMetricsFile / observation / recompute_signals / Signal / 五截断点）→ 见维护指南 指标与健康。

事实源：v1-onboarding-overview.html Tab②、plan/18。
维护指南 · 机制 01

架构与铁律

整套产品的工程底座与不可妥协。后续每个机制章都建立在这之上。

用到此机制的阶段：全部

crate 全景

bw-core
领域内核：StageKind / Issue 状态机 / 度量派生链。零 IO 零 UI，wasm32 可编译。
bw-engine
Executor trait + ClaudeCliExecutor + evidence.rs。
bw-store
SQLite（sqlx）：schema.sql + add_column_if_missing；append-only 表。
bw-app
编排大脑：Command/Event 总线，用例与守卫主战场。
ui
纯函数 selector + ViewModel，wasm32 可编译。
app-desktop
真壳（Dioxus 0.7 hard-pin 0.7.9）。app-web 留口不编译。

两个不可妥协钉进类型与 CI

01
UI 无关内核
五个内核 crate 禁依赖 dioxus/tauri/wry，guard 脚本 + wasm32 check 可证。
02
健康永远 derive
Signal 只能经封口 Derived<Signal> 进缓存，store 无 set_signal。

铁律四条

01
管理体系自带
挂仓即自动建三件套与五阶段。
02
活让 agent 干，人守验收
Done 唯一入边 = InReview，永不自动完成。
03
健康难造假
Signal derive-only，无数据即 Unknown。
04
经验复利
蒸馏 → 注入 → uses+1。

三个事实源

仓 codehub/github
产品信息正本。指标定义 .bw/metrics.toml 也在仓里。
SQLite store
过程信息，append-only。project 行、observation 等落此。

纳入时的幂等守卫、project 行落库都在 store 层（重复提交不产生脏数据，已修）。

事实源：CLAUDE.md · 架构 / 核心纪律、DEVELOPMENT.md。
维护指南 · 机制 02

Hub 全局库

跨阶段的共享资产层，project_id=NULL。纳入、找指标、绑数据、总览都经它——connector 供纳入与采数，skill 供找指标与绑数据加载。

用到此机制的阶段：纳入找指标绑数据总览

六套件

connector 连接器
git-repo / CodeHub / GitHub / claude-cli（+ script 计划中）。纳入时建 2 个；采数经它。
skill 技能
6 渠道，唯一能 CRUD 的地方。找指标/绑数据加载预制技能。
agent 智能体
五角色全局单例（原型师/构建师/优化师/运营推广师/运维师）。
workflow 工作流
五阶段 template + 自建。
cron 定时
4 mode 分发（collect_metrics / run_skill / run_prompt / run_stage_playbook）。
knowledge 知识
留口未建。

connector 与 Remote 工厂

connector
buddy 与远端仓/CLI 的适配抽象。纳入项目时建 2 个：git-repo + provider 适配；总览阶段采数也经 connector。
事实源：bw-store、CLAUDE.md
Remote 工厂
provider 分叉（codehub / github）收敛一处。新增 provider 只改工厂。
事实源：CLAUDE.md · 架构

skill 六渠道

skill 6 渠道
Boot seed / 手建 / 蒸馏 / 导入单包 / 批量导入 / 项目仓自带扫描（种A：只登记可见、不进注入下拉）。
事实源：CLAUDE.md
技能注入/蒸馏复利见「技能与 Prompt」章。
维护指南 · 机制 03

Issue 与调度

找指标、绑数据本身都是 Issue 被调度执行。纳入时三件套也是 Issue 自动建。调度贯穿全流程。

用到此机制的阶段：纳入找指标绑数据

Issue 状态机

状态机
Backlog → Todo → InProgress → InReview → Done，另有 Blocked / Cancelled。Done 唯一入边 = InReview，且必须人显式点。
事实源：bw-core

调度执行

RunIssue
issue 卡触发 AI 真开工。干完只到 InReview，不到 Done。
事实源：bw-app
Run 运行
一次真实执行，有成败/耗时，全结局入账。
事实源：bw-store

自动与留痕

autopilot / cron no-hijack
到点只建活、永不自动完成活。AI 永远不能替你点 Done。
事实源：CLAUDE.md · 核心纪律
标配三件套自动建
纳入项目末尾按依赖序自动建 3 张起手 Issue：竞品分析 → 找指标 → 绑数据。
事实源：plan
铁律②的落地Done 唯一入边 = InReview + no-hijack，是「健康难造假」的根基。详见「架构与铁律」章。
执行器本身见「执行与证据」章。
维护指南 · 机制 04

技能与 Prompt 加载

找指标、绑数据都加载系统预制技能（north-star-discovery / metrics-binding）。技能是 buddy 的复利资产。V1 起 skill 方法论可换（业界 skill 也行），buddy 衔接层 system prompt 不可换——包项目上下文 + 契约 + 铁律。

用到此机制的阶段：找指标绑数据

系统预制技能

三件套技能
north-star-discovery（找指标）/ metrics-binding（绑数据）/ competitive-analysis（竞品分析，联网墙未解）。
事实源：docs/skills/
五阶段方法论
baseline-before-touch / breaking-drill / evidence-first / fresh-eyes-funnel / spec-to-tests。
事实源：docs/skills/

交互式 skill 注入（V1）

衔接层 system prompt 不可换
--append-system-prompt 灌项目上下文（PlaybookCtx：desc/benchmark/opportunity/north_star）+ buddy 契约（写 .bw/metrics.toml 按 script|manual 两 kind、读 governance//derive_*.py 优先对齐、产 metrics-rationale.md、绑数据建 script connector 经正规 create_connector）+ 铁律（Done 不自动/settle-once/signal derive-only/Unknown≠绿）。任何 skill 进来都包这层。
事实源：bw-engine/src/interactive_cli.rs · build_bridge_system_prompt
skill 方法论 可换
skill 正文经位置参数 prompt 注入（本机 claude --help 无 --prefill，用位置参数等价 auto-send；--prefill 字段留 forward-compat）。buddy 自带 north-star-discovery/metrics-binding，业界 skill 拿来当 prompt 注入也行——衔接层包住它，产出仍对得上契约。
事实源：bw-engine/src/interactive_cli.rs · build_startup_plan、docs/skills/
声明式 CLI 表
TuiAgentConfig 静态表，claude 支持 / cursor 占位（先不接）。加新 CLI 加一行配置，不是新 impl。
事实源：bw-engine/src/interactive_cli.rs · CLAUDE/CURSOR
权限
交互式 --dangerously-skip-permissions（流体操作不老问）+ --disallowedTools "Bash(gh pr merge)"（守"人 merge"铁律——跳权限询问 ≠ 绕 deny 名单）。后台 one-shot 休眠轨留 acceptEdits。
事实源：bw-engine/src/interactive_cli.rs · build_startup_plan
注入/蒸馏复利链见下；CRUD 在 Hub 全局库。嵌入终端（PTY/xterm/hook→事件）Phase 2 未建，见设计 docs/v1-prototype/issue2-metrics-interactive-loop.md。

注入与复利

skill 注入
干活时自动把最相关技能带进队友上下文。
事实源：CLAUDE.md
蒸馏 → 注入 → uses+1 复利链
做完的活提炼成技能（distill 记来源活），下次干活自动注入最相关技能，uses+1。战绩/胜率由真实成败派生，永不手设。
事实源：CLAUDE.md
种A
项目仓自带 skill 扫进来登记可见，不进任何注入下拉。见 Hub 章。
事实源：CLAUDE.md
技能 CRUD 在 Hub 全局库（skill 套件）。
维护指南 · 机制 05

执行与证据回流

AI 真开工靠 shell-out 本机 claude CLI。V1 起两轨：后台 one-shot（autopilot 建活）+ 交互式 claude CLI（找指标/绑数据，人 in loop 搭装置）。核心纪律：不信执行器自报，evidence 从工作区真实状态回流。

用到此机制的阶段：找指标绑数据

执行器热插拔（one-shot 后台轨）

Executor trait
抽象 AI 执行，MockExecutor / ClaudeCliExecutor 热插拔。
事实源：bw-engine
ClaudeCliExecutor
shell-out claude -p --permission-mode acceptEdits --allowedTools Bash。BW_CLAUDE_BIN 给全路径（Windows Rust Command 不做 PATHEXT）；BW_CLAUDE_MAX_BUDGET_USD 单次封顶。
事实源：bw-engine
MockExecutor
流程演示替身，产出自我标注【mock】，绝不冒充真实。
事实源：bw-engine

交互式执行（V1 · 人 in loop 轨）

InteractiveCliExecutor
交互式 spawn claude（不带 -p），用户多轮对话，跑完只到 InReview（Done 永不自动铁律不破）。Phase 1 = 系统终端 spawn + 等进程退出（+ wall-clock 兜底）；嵌入终端（PTY + xterm + hook→事件）Phase 2 未建。零扰 one-shot Executor trait / ClaudeCliExecutor / run_workflow。
事实源：bw-engine/src/interactive_cli.rs、bw-app/src/lib.rs · run_issue_interactive
会话即记录 不额外摘要
嵌入终端 scrollback + session.jsonl 本身是对话记录，buddy 不解析摘要。buddy 只留文件级 evidence：HEAD 对 diff + artifact 登记 + 状态/PR#（+ 可选 usage 读回）。
事实源：bw-engine/src/interactive_cli.rs · SkillOutput、bw-app/src/lib.rs · finalize_run_interactive
预算 wall-clock
--max-budget-usd 只配 --print，交互式用不了；用 wall-clock 超时 + jsonl usage 诚实读回。对"单次花费封顶"是显式偏差（交互式 user-in-loop 花费眼看着，不像后台 runaway；orca 同款）。
事实源：bw-engine/src/interactive_cli.rs · await_child
MockInteractiveExecutor
无 claude/网关环境的交互式替身，产出自标【mock】+ 写占位 .bw/metrics.toml。
事实源：bw-engine/src/interactive_cli.rs
已知 gap（Phase 2 修）：交互式 run 不建 workflow_run 行→运行史暂不可见；macOS 完成检测只靠 timeout。真交互式 E2E（嵌入终端 + 真 claude）defer Phase 2 + 用户驱动；Phase 1 验证 = 门禁 + mock 单测 + code review。设计见 docs/v1-prototype/issue2-metrics-interactive-loop.md。

证据回流

evidence.rs
从工作区真实状态回流观测，不信任执行器自报。
事实源：bw-engine
读回为证
数字一律 sqlite3 SQL 读回，过程数据 append-only 可查证。
事实源：CLAUDE.md · 核心纪律
调度入口 RunIssue 见「Issue 与调度」章。
维护指南 · 机制 06

指标与健康体系

贯穿找指标（产出定义）、绑数据（接采集）、总览（采数重算点亮）。价值闭环的五截断点由 plan/18 修通。

用到此机制的阶段：找指标绑数据总览

指标定义

.bw/metrics.toml 指标正本
仓里机读文件，非 buddy 私有配置，改指标走 PR。含北极星 + 引领/滞后 + 目标值 + 比较符 + 黄区带。找指标阶段产出。格式见 docs/metrics-toml-format.md。
事实源：docs/metrics-toml-format.md
北极星 / 引领·滞后
North Star = 项目唯一顶层目标（maas 实例 = 定界结论采纳率 (L2−L3)/L2）。Leading = 可控先行量；Lagging = 结果量。
事实源：CONTEXT.md

采集

采集器四类
github / connector / bw / manual（带徽）；+ 计划中 script。绑数据阶段接采集方案。
事实源：CLAUDE.md
probe vs collect
probe = 探活翻已连接；collect = 真采计数写 observation。总览阶段才真采。
事实源：CLAUDE.md
observation 表
append-only：一个观测 = 一个点，绝不插值；无观测即 Unknown。
事实源：bw-store/schema.sql

装表·重算·点亮

SyncMetricsFile
merge 后把 metrics.toml 装进 metric 表。
事实源：bw-app
recompute_signals
由观测重算 Signal。观测变 → Signal 重算。
