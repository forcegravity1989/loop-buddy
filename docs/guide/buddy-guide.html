使用指导 · 概览

一个 Builder + Agent Loop 的项目管理工作台

Builders' Workbench（口语「buddy」）把传统项目管理的 5 角色 10 流程压成「1 个构建者 + AI 执行小队」。人守质量门与验收，活让 agent 干。本使用指导按界面操作的一个个阶段组织——实践推进到哪，就写到哪。

当前阶段实践到、能见到的

纳入项目→ 找指标→ 绑数据→ 总览呈现→ 健康灯亮

四个阶段各对应一屏（纳入/找指标/绑数据/总览），每屏写操作 → 结果 → 看到。后续阶段随实践推进补在后面。

面向谁

Builder / 构建者
端到端 own 项目的单人，全局唯一，专指人类。
边界
不是团队协作/通用看板/审批系统/云服务。AI 执行 = 本机 claude CLI。

四个控制点

01
知道对标谁
北极星唯一，引领指标可控先行。
02
每周在正常演进
可验证增量替代甘特图，真实 telemetry 难造假。
03
agent 干活，人守验收
干完只到 InReview，Done 永远人显式点。
04
目标清晰且难造假
无数据即 Unknown 而非绿色。
两本怎么配合使用指导按操作阶段讲操作与结果；维护指南站在更高 level，按跨阶段共享的机制汇总——一个机制服务于多个阶段（如 connector 既用于纳入又用于采数，技能加载既用于找指标又用于绑数据）。每章顶部用阶段徽标出用到它的阶段，阶段屏末用 linker 指回涉及的机制章。
事实源：plan/07-product-proposition.md、CLAUDE.md。
使用指导 · 前置准备

开工前先装齐这些

buddy 是本机桌面应用。装齐下面三样，再启动即可；数据库与工作区有默认路径，一般不用配。

必装

git
项目纳入靠 SSH clone。
claude CLI
本机能跑通 claude，buddy 靠它真开工。
codehub-cli / gh
按仓所在平台选装：CodeHub 用 codehub-cli（需登录态 / token）；GitHub 用 gh。列仓、开 Issue、采指标都靠它。

选装从源码构建时才需要

Rust 工具链 + mingw开发
本地 cargo run -p app-desktop 构建桌面壳。

启动

cargo run -p app-desktop
Windows请用上面这条启动，别直接跑 target/ 下 exe（会以 0xC0000135 崩溃）。若找不到 claude，再设用户环境变量 BW_CLAUDE_BIN 指向 claude.exe 全路径。
数据库与工作区默认在本机用户目录下的 BuildersWorkbench；一般不用改。
使用指导 · 阶段 01

纳入项目

V1 主推接入已有仓：选平台 → 选仓 → 填名字点确认。buddy 负责 clone、挂连接器、排定时器、建三张起手 Issue、扫你仓里已有的 skill——你只管后面跑那三张活。

操作两张卡

1
项目墙点「新建项目」，进入创建流
2
「仓从哪来」：选平台（codehub/github）；起点选「新建仓」或「接入已有仓」；codehub 选区域（绿区/内源/黄区，三个都可点；选择器下方如实标着「green/open 已登录可直用；yellow 需先在本机 codehub-cli -H yellow auth login」，没登录就选黄区，建仓/拉列表会失败并弹人话报错）；接入已有点「↻ 刷新列表」后从下拉选
3
「你想做什么」：项目名称（必填）+ 一句话意图（可不填）+ 对标谁（可不填，竞品分析用）+ 三个月后怎样算成了（可不填，找指标用）
4
点「确认 · 建立项目」——一个按钮，背后连发整链；进度见上方条，完成后进项目
接入已有仓时下拉只列出你当前登录能看到的项目——关联不到的仓选不了，也不能手填路径绕过。

背后确认建立后系统执行了什么

对远端代码仓（GitHub/CodeHub）
  • 接入已有：不改你远端历史；在远端开 3 个 Issue（竞品分析 / 找指标 / 绑数据）
  • 新建仓：创建空仓，再开那 3 个 Issue；并把本地写的章程/标准 push 上去（根目录 PROJECT.md + .claude/standards/{agent,skill,workflow,cron}-standards.md）
对你的机器
  • 把仓 clone 到 buddy 工作区（默认 %APPDATA%\BuildersWorkbench\workspaces\<名>-<短id>）
  • 仅新建仓：写 PROJECT.md + 四份 .claude/standards/*.md。接入已有：不动你仓里的文件
对 buddy 数据库
  • 落一条项目记录、铺开五阶段、挂 2 个连接器（仓连接器 + script 仓统计）和一条每日定时器（名如「… · 采集代码仓指标」）、建 3 张起手 Issue、种代码仓指标；创建收尾会采一次——有值就显示，没值灰着（Unknown ≠ 绿），也可在总览点「立即采集」

细节见维护指南 Hub 全局库 / Issue 与调度 / 指标与健康。

得到什么建立完成后的结果

  • 项目在墙——点进运营屏；侧栏能看到扫到的本项目 skill / 定时器 / 连接器
  • 总览 · 项目指标两张仓卡（开放 Issue 数 / 已合入 MR 数，不点健康灯）+ 阶段完成一行；创建后常已有数，也可「立即采集」
  • 3 张起手 Issue（竞品分析 → 找指标 → 绑数据）在 Issue 看板 Backlog——下一步开跑（找指标/绑数据见 u3/u4；竞品分析见下）

竞品分析三件套之一怎么用

起手三件套里的①「竞品分析」需要联网抓取对标产品的公开页面。当前本机 claude 环境暂不支持这类抓取——点了会失败。联网能力就绪后再开跑；现阶段先留着这张活，其余两件套可正常跑通。

想看「连接器 / 定时器 / 三件套」怎么设计的 → Hub 全局库 + Issue 与调度。

事实源：实跑 cowelink 接入已有（2026-08-06）；纳入设计见 docs/v1-prototype/issue1-onboard-simplify.md。

绑数据

一句话：把「打算怎么采」搭成真装置——能自动的写脚本登记连接器，不能自动的保持手填。合入后不用新建定时器：原来那条每日采集会跑本项目全部脚本。

▶跑

→

→
合入完成
同步进 buddy
→
每日采集
跑本项目全部脚本
→
出数
总览业务卡有值

操作

1
「绑数据」点 ▶跑(交互)——它会读你已合入的指标计划
2
能自动采的：让模型写脚本并登记到 .bw/connectors.toml；只能手填的：保持计划即可
3
提合并请求 → 看板 ⬇ merge PR（或网页合完再点「已完成」）
4
总览点「↻ 立即采集」，或等每日定时，看业务卡是否出数

看左侧「连接器」：除了仓本身，还应出现你刚绑上的业务脚本。定时任务多半还是原来那一条——这是正常的。

和模型核对这三件事

请确认正确样子不对时你会看到
连接器表头写成 [[connector]]（单数）同步时报错，侧栏多不出新连接器
脚本怎么交结果写到约定的结果文件里只在终端打印 → 总览一直采不到
本机怎么跑脚本用你机器上真有的命令（Windows 常见 py）采集失败、业务卡仍灰
定时器怎么理解
面板上多半仍只有一条「… · 采集代码仓指标」。别被名字骗了——到点会跑本项目每一个采数脚本（仓统计 + 你绑的业务脚本）。文件里写的采集周期不会再多出一条定时任务。

使用指导 · 阶段 04

总览呈现

一句话：每周看这一屏就够——上面是仓的现状数（不点灯），下面是业务健康（点灯）。没采到就灰，不替你假装绿。

一屏怎么读
项目指标
开放 Issue / 已合入 MR… · 不点灯、不上卷业务健康
业务指标
北极星 → 滞后 → 引领 · 有数才可能亮；没数就灰
buddy 情况
待合入、本周未记… · 「完成」只能你点

操作

1
阶段轴点「◎ 全部阶段 · 总览」
2
自上而下扫三层；灰卡 = 还没采到数，或还没绑上采集方式
3
想立刻出数：项目指标区「↻ 立即采集」
4
你在仓里改了指标计划、还没走合并：业务区「↻ 同步指标文件」（只同步计划，不采新数）

上图：上面仓指标已有数；下面北极星 / 周新增仍灰——要么还要手填，要么自动采还没跑成功。没数就灰，不会假装绿。

三个易混概念

你看到的实际意思
「手动 / 脚本」标注这是采集计划，不是「已经有数」
灰卡 / —还没有采到的数值（不是绿灯）
「手填」徽这条数是人手填的；总览卡上暂时还不能直接填
折线旁 → 0.0可能是空周沿用了上周，不是「稳住了」——留意「本周未记」
杂项点完成时若提示「登记了 N 个产物」，N 往往接近整仓文件数，不是业务产出件数。删项目只清 buddy 里的记录，重建前请自行清掉本机工作区目录 workspaces\<名>-*。

维护指南 · 机制 01

架构与铁律

改 buddy 前先建立分层心智：谁能依赖谁、健康从哪来、完成谁说了算。本章是其余五章的底座。

用到此机制的阶段：全部

分层栈谁依赖谁

数据 / 意图自上而下 · 领域自下而上
app-desktop
桌面壳（Dioxus）。唯一允许碰 UI 框架的地方。用户点按钮 → 发意图。
ui
纯函数：状态 → 可渲染 DTO。无 IO。
bw-app
编排大脑：用例、守卫、调度、重算。几乎所有「业务发生」都在这。
bw-store
SQLite 哑存储。观测/交棒只追加；信号列是缓存，不是手填入口。
bw-engine
真干活：claude CLI、远端仓 API、工作区证据、指标/连接器文件解析。
bw-core
领域内核：五阶段、Issue 合法转移、派生类型。零 IO、零 UI，须能编到 wasm。
不可妥协 · 01
  • 内核五 crate 禁止依赖桌面/Web UI 框架
  • 改界面 ≠ 改领域；CI 有守卫脚本
不可妥协 · 02
  • 健康灯只能由观测重算得出
  • store 没有「手设 signal」；无数据 = Unknown ≠ 绿

四铁律产品边界

01
管理体系自带
五阶段打法内置；挂仓即搭起手装置。
02
人守验收
Done 唯一入边 = InReview；agent / cron 到不了完成。
03
健康难造假
观测只追加；settle-once；手填戴徽。
04
经验复利
蒸馏 → 注入 → uses+1；胜率由战绩派生。

两套事实源

源管什么落点（默认）
远端代码仓产品正本：代码、指标定义、装置脚本、章程用户仓 remote；clone 在工作区

维护指南 · 机制 02

Hub 全局库

跨项目的资产面：连接、脚本、定时、技能、队友、工作流。纳入时自动挂「能采数的最小装置」；后续找指标/绑数据在这上面长业务装置。

  • connector：知道怎么连外部系统并探一次（如 codehub-repo / github-repo）。
  • script：干采数活的脚本实体（表里 kind=script）。buddy 自带「仓统计」；业务脚本由绑数据写入仓后再 sync。

  • 本地工作区探活：clone 后直接读 git/docs/测试回流，并扫项目 skill（种 A）——不建成 connector 行。

要点正确踩坑

Example · 接入已有 codehub 仓

Issue 与调度

  • 交互式进 InReview：不信 agent 自报；buddy 查远端是否确有该分支的开放 MR/PR，有才转入并记 pr_number。

  • settle-once：第一次进入 Done 记账；重开再完成不双计（settled_at）。
