怎么干活

一个项目接进来一次,之后每周转一圈,一圈六站(下面那张图就是这一圈)。你做的事只有两类：说清楚要什么，以及在关键路口点头。剩下的——查资料、写代码、写文档、提交、开 MR——交给 agent。

所以整份指南只有一条主线：接进来 → 每周定目标 → 派活 → agent 干 → 你验收。

六站旅程环一个项目每周怎么转

0 只做一次，已经真走过；1–6 是设计，还没真走完一圈
实心 = 已经真走过一遍 虚线 = 设计定了，还没真走完这一站

这份指南跟着实践走：每走完一站、那一站的改动合入之前，把这一站从「还没走到」搬进「已经走过」。今天只有第 0 站是实心的。

两条你随时可以拿去核对的规矩「完成」永远由人点：agent 干完最远只到「评审中」；定时任务只会自动建活，绝不自动完成活。没数据就是灰，不是绿：健康灯只能从真实数据推出来，界面上任何一个数字都能用 sqlite3 直接查库核对。
设计正本 docs/v4-prototype/design.md;还没做的活只认 docs/LEFTOVERS.md。
怎么用 · 第 0 站

把一个项目接进来

这一站已经走过，下面写的都是实际发生的。

你要准备什么

一个 git 仓
GitHub 或 codehub 上的都行，你有它的读权限。
本机装好命令行工具并登录过
gh（GitHub）或 codehub-cli（内部）。项目墙上那条环境条会当场去 PATH 里找这些命令，找得到绿、找不到红。红的不影响别的事，只影响对应那条路能不能走。

工作区目录先看一眼

「设置」里有一格「工作区根目录」。以后接进来的项目，仓就 clone 到这个目录下面，一个项目一个子目录。默认值在 macOS 上是 ~/.builders-workbench/workspaces，Windows 上是用户目录下的同名路径；要放到别的盘，现在就在这格里改掉、点保存——改完立刻生效，重启还在，而且已经接进来的项目不会跟着搬家（它们的路径当场被钉死在原处）。

接：两步

1
点「+ 接入项目」。第一步只问一件事：这个项目在哪。光标点进「项目地址」那格，buddy 就去问平台要你账号下的仓，列成下拉框；打字即在这批里检索，点一行即选中。不想理列表就直接把 owner/repo 打进去，一样算数。框里右边那个 ⟳ 是重新拉一次。
2
第二步是基础信息，四格：项目名称、你想做什么、最像的对标、三个月长成什么样。
列不出来的时候会把命令的原话摆给你看（多半是没装或没登录），不会摆一张假列表。

第二步顶上：这个仓被 buddy 接管过没有

判据是去它远端读 .bw/project.toml：

你会看到意思你该做什么
已经被 buddy 接管过同事先接过，或者你以前接过四格是回显出来的，直接改就行；接进来时不会覆盖仓里已有的字
还没被 buddy 接管过仓在、就是没这份文件四格自己填
找不到这个仓地址敲错了、私有仓没权限、没登录先把地址改对，接一个不存在的仓后面每步都会失败
没查成网不通、默认分支不叫 main照样能接；仓里真有名片的话，接入时以仓里的为准

最后两行是特意分开的：「没查成」不等于「没被接管过」。混成一句的话，你会照着空格子填一遍，接进去反而把仓里真正的名片盖掉。

点「完成接入」之后会发生什么

界面上一步一句地摆出来，做完的那行原地换成结果——这一下要十几秒，别猛点：

1
取仓——目录里已经是 git 仓就直接用（顺带把它的 origin 报出来给你核对）；目录不在或是空的就 clone；没填远端就建个空目录并说明它是空的；目录里有东西又不是 git 仓就当场弹回，既不敢往里 clone，也不敢把别人的目录当成这个项目的仓。
2
库里落一行项目——只存定位：名字、本机路径、远端地址。名片不进库。
3
写名片——.bw/project.toml。仓里已经有就一个字不覆盖、只补空着的字段。
4
自动建一张「规范铺底」的活——它开一条分支、往仓里写规范骨架、提一个 MR，然后停在评审中等你合。它不会自动合，也不会自动把活标成完成。
5
自动进这个项目。

第 4 步这次只铺你马上要用的三份，不是一口气铺二十几份，而且全在 .bw/ 底下：

文件是什么
.bw/PROJECT.md项目名片：这个项目是什么、对标谁、北极星是什么
.bw/standard.toml铺的是哪一版规范、开了哪几类件

（另外还有第 3 步写的 .bw/project.toml 和一份记指纹的 .bw/managed.toml，一共五份，全在 .bw/ 里。）其余的——指标正本、活的分类映射、周计划目录、发版记录、设计文档目录——等你第一次真的走到那一站再出现。想提前补齐，「配置」屏那颗「规范铺底」按钮点一次就全铺上。

两件事你会注意到

  • buddy 铺进你仓里的东西，全都在 .bw/ 里，一个例外都没有。仓根一个字不动——README.md、AGENTS.md、CLAUDE.md、docs/，接项目这一步全都不碰。「哪些是 bw 的资产」ls .bw/ 一眼可数。
  • buddy 自己的规矩不往你仓里写。完成由人点、指标只能真采、合并永远是人——这些每次开工都会现给 agent，写进你仓里只会变成第二份会过时的副本。
  • 想让 buddy 给你的项目写一份开发手册（仓根 AGENTS.md：怎么建、怎么跑、怎么测、目录里什么在哪）——那是另一件事，不在接项目这一步。它归「资产盘点」：buddy 起一次会话真读一遍你的仓，把读出来的摊给你看，问你要不要，你点头才写，写完还是一个 MR 给你评审。给你的项目加规范是在改你的项目，得先问过你。（这一步还没实现，见 docs/LEFTOVERS.md。）
  • buddy 自带的技能不会进你的仓。它们住在 buddy 自己的目录里，agent 开工时 buddy 只把这张活要用的那一份的名字和路径告诉它，正文让它自己去读。你仓里 .claude/skills/ 下的技能仍然是你自己的，buddy 不碰。

你仓里本来就有的 README.md、CLAUDE.md、AGENTS.md，buddy 根本不碰——不是「已存在就跳过」，是这一步压根不往仓根写东西。

第 4 步没成不会推翻前面：项目已经接进来了、仓已经在本机了，这两件是真的。回头在「配置」屏点一次「规范铺底」重来就行——它按标题幂等，重来不会多建一张活。

接错了怎么办

项目卡右上角有个 ✕。点一下先问一句，再点「移走」才真移走。它只把这个项目从工作台移出去（项目行、它所有活的账），仓一个字节都不动——硬盘上的代码还在原地，活自己的工作目录也还在。回执里会告诉你仓在哪儿，你真要删自己去删。

这一站结束时你手上有什么

  • 本机一个真实的仓（clone 下来的）
  • 工作台上一个项目
  • 一张停在「评审中」的「规范铺底」活，和它在远端的 MR

下一步是去合那个 MR。合完这个仓就有管理体系的正本了。

健康灯怎么亮只从真实数据推,不能被人调

「周一看总览」这一站还没走过，具体判断依据没有实践细节可写。以下是这份指南能如实说的部分——来自「两条你随时可以拿去核对的规矩」和对外宣讲稿里对同一屏的描述，先立住机制形状，细节等真走过再补。

数据推导，不能手点；没数据就停在灰

灯下面那三条理由,界面上原样显示的就是这三句(成立打勾、不成立打圈):

  • 本周定了周目标,仓里也有真实提交 —— 不成立时会具体说是哪一半没满足:「本周还没有周计划文件或周目标是空的」,或者「本周有周目标,但仓里还没有真实提交」。
  • 本周或上周的周计划文件里有指标读数 —— 不成立时显示「最近两周都没有记过指标读数」。
  • 上周有合入或发版 —— 不成立时显示「上周既没有合入也没有发版」。

三条怎么合成一盏灯(什么时候黄、什么时候红、为什么没数据是灰不是绿),见设计正本 docs/v4-prototype/design.md 第 5 章。

一件活怎么走到完成唯一入边是评审中

agent 只能推到评审中；完成只有一个入口，且必须是人点的
完成 = 锁定态，只能人工点开 红色虚线 + × = 定时任务被结构性挡在完成之外，不是靠自觉

特性开发维护

代码分成哪几块

这一部分给要给 buddy 开发新特性的人看：代码分成哪几块、命令怎么跑、提交前要过哪些检查、怎么证明自己做的东西是真的。产品行为怎么设计的看 docs/v4-prototype/design.md；仓库整体的工作纪律（写作纪律、核心纪律）看仓根 CLAUDE.md；领域词查仓根 CONTEXT.md。

V4 有三个 crate，对 V3 那六个 crate 零依赖。V3 那套（bw-core / bw-engine / bw-store / bw-app / ui / app-desktop）只保证继续编译，不为 V4 改它们。什么时候能删，判据在设计正本第 12 章。

三个 crate 的关系

app-shell 依赖 bw-v4 与 v4-engine；standard/ 被 bw-v4 读入做规范铺底；对 V3 六个 crate 零依赖（cargo tree 读回为 0）
crate是什么
bw-v4V4 内核：四张表的本机库（项目 / 活 / 会话 / 元信息）+ 仓文件解析（.bw/PROJECT.md、.bw/*.toml、.bw/plan/ 周文件、.bw/releases.md）+ 现算推导（健康灯、周列表、走势）+ 自己的一对命令/事件总线 + 规范铺底 + 三张运作活 + 项目群工厂。零 IO 之外的 UI 依赖，在「内核不依赖界面」的稽查名单里。
v4-engineV4 的能力底座（2026-08-21 从 bw-engine 拷过来接管，不是复用）：交互式 claude 执行器、伪终端内嵌终端、每张活一棵工作目录的供给、git 读数、GitHub / codehub 两个远端。只认裸 uuid，不认业务语义。
app-shellV4 新壳（Dioxus 0.7）：九屏（项目墙 / 接入 / 设置 三个顶层 + 总览 / 计划 / 会话 / 通知 / 配置 / 知识库 六个项目内入口）+ theme + bridge（独立线程跑内核）+ adapters/（一个外部能力一个目录，各带一份 README）。二进制名 bw-v4-dev。
standard/规范件正本（和 crates/、docs/ 平级），编译期打进二进制。改它就是改产品行为，不是改文档。skills/ 下是 buddy 自带的技能与运作剧本，一个平铺目录。

app-shell 的九屏项目内六入口 + 三个顶层屏

三个顶层屏不依赖具体项目；六个入口都挂在某一个项目下面

为什么是拷贝不是复用

V3 那一整个目录最终会被整体删掉，所以 V4 不能有任何一条依赖指向那边——包括「只依赖 V3 的能力层」这种看起来很轻的耦合，因为它自己还依赖 V3 内核，会顺着传递过来；而改 V3 的能力层又会动到还在跑的 V3。拷一份两边都不牵连。

特性开发维护

常用命令 · 门禁

命令改了这里就得改；写不确定的东西不如不写。

常用命令

cargo check -p bw-v4              # V4 内核日常编译检查（不编 Dioxus，最快）
cargo run -p app-shell            # 启动 V4 新壳（二进制名 bw-v4-dev）
./scripts/bundle-desktop.sh v4    # 打成 dist/BW-V4.app（macOS；Windows 包见 LEFTOVERS）
./scripts/point-bwdev-here.sh v4  # 把当前二进制拷进 ~/Applications/BWDev.app（computer-use 用的稳定壳）

门禁提交前这一组全过

cargo fmt --all --check
cargo clippy --workspace --exclude app-desktop -- -D warnings   # 本机连新壳一起查
cargo check -p bw-core --target wasm32-unknown-unknown --no-default-features
cargo check -p ui --target wasm32-unknown-unknown
./scripts/guard-kernel-ui-free.sh          # 内核 crate 不许依赖界面框架
./scripts/guard-no-cross-screen-import.sh  # 一屏一模块：屏与屏之间不互相 import
./scripts/guard-file-lines.sh              # 单文件 1500 行硬上限、600 行软提醒
./scripts/guard-screen-hooks.sh            # 用 Dioxus hook 的函数必须是组件
cargo check -p app-desktop                 # 旧壳编译过
cargo check -p app-shell                   # 新壳编译过
cargo test --workspace --exclude app-desktop
本机比 CI 多查两样，不是笔误两个壳都吃 Dioxus / wry 那棵树，在 Linux 上要系统 WebKit / GTK，而 CI 那台机器上没有对应的库，构建脚本在 clippy 看到任何代码之前就链接失败。所以 CI 把两个壳都排除掉，壳的 clippy 只在本机跑。三个结构守卫是纯文本检查、不编译，CI 里照跑——新壳的布局规矩每次 push 都拦。

那三条守卫各自在拦什么

  • 屏与屏不互相引用——共享数据要经共用的 ViewModel 模块或者绕命令/事件一圈，不许一屏直接伸手进另一屏。
  • 文件行数——老 buddy 走不下去的原因之一是某个文件动辄一万多行，改一处散弹一片。新壳是重写不是迁移，没有「存量文件一时改不完」的过渡借口。
  • hook 必须在组件里——这条是评审抓到真 bug 之后补的：普通函数在渲染宏里被直接调用时，它的 hook 落在调用方的槽位上按序号取；切一次屏，序号还在、类型换了，取的时候类型转换失败，整次渲染崩溃，用户看到的是一块空白面板，编译期一点征兆都没有。放进循环里更糟：hook 数量随列表长度变，行与行的输入框内容会串位。
特性开发维护

环境变量与深链 · headless 例子

深链 = 用环境变量直接启动到指定项目 / 指定屏，是 V4 最主要的验证手段之一。启动时标准错误上会打两行证据日志：[BW_OPEN] …（深链解析结果）与 [BW_BOOT] …（界面已渲染的证明）。

环境变量

变量干什么
BW_DB覆盖库路径（默认 macOS ~/Library/Application Support/BuildersWorkbench/workbench-v4.db，和 V3 的库文件同目录不同名）
BW_WORKSPACES覆盖工作区根目录
BW_OPEN=<项目 slug 或名字>
+ BW_PANEL=overview|plan|session|notify|config|kb		打开项目内六入口
BW_VIEW=onboard|settings打开不依赖项目的顶层屏（项目墙是默认视图，不需要变量）
BW_SEL=<kind>:<uuid>定位到具体一张活
BW_PTY_DEBUG=1内嵌终端把初始化结果与键盘字节打进标准错误
BW_KB_DUMP=1把知识库三个页签的数字打进标准错误（每组几个文件、代码图头一名是谁多大、资产五个区块各几条）——截图对不了数，这个能

假群每发一条通知也会打一行 [BW_CHAT_SENT] …。

遇到不认识的枚举值会如实打印「未知值」，不静默退回某个默认屏——静默 fallback 会让你以为深链生效了。

headless 例子不开界面直接驱动内核

每一个都是读回证据，不是演示脚本：它们跑完会把「凭什么这么说」的命令一起打出来，数字对不上就是代码错了。全部不碰 claude、不碰网关。

例子验什么跑法

特性开发维护

怎么验证：三句话

行为正确性靠端到端验证，不靠测试基线。

1
任何「已完成 / 数字是 X」的说法，必须能用 sqlite3 从数据库、或者打开仓文件独立查出来核对——这叫读回。
2
深链启动后标准错误出现 [BW_OPEN]，就是「界面真的渲染了」的证明。
3
产品的不可违反约束（完成永远由人点、信号绝不手设）钉在类型和守卫里，编译过就守住了，配合 /code-review 与读回抽查。

几条常用的读回

# 库里恰好四张表，一张不多
sqlite3 <db> "SELECT name FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%';"

# 本周业务活数与仓文件一致（缓存对文件）
sqlite3 <db> "SELECT COUNT(*) FROM issue WHERE project_id='<pid>' AND kind='business' AND week_of='2026-W34';"
#   ↑ 应等于 <ws>/.bw/plan/2026-W34.md「业务活」表格的行数

# 自动建的活绝不被自动推进到完成
sqlite3 <db> "SELECT COUNT(*) FROM issue WHERE kind='ops' AND settled_at IS NOT NULL;"   # 期望 0

# 项目群配置不在库里 —— 查不到就是预期
cat <ws>/.bw/project.toml     # 看 [chat] 段

「实际输出」要真实粘贴，不是转述——拿截图或者 agent 自报当读回，正是这条纪律要避免的反例。

关于内联单元测试（如实表述）仓里现存约两千行内联测试，CI 的 cargo test 在跑，它们必须过。纪律是：不要求写、现存的随 CI 跑、改到就顺手维护、不建回归大坝——别把「补测试」当成交付物，也别删掉在跑的。
用 computer-use 摸桌面应用的已知坑
~/Applications/BWDev.app 是长期稳定的验证壳，跑一次 ./scripts/point-bwdev-here.sh v4 就能接上，不要新建 app（同一次会话里现造的新身份认不出来）。截图真实可用，点击和键盘永久受阻——两种打包方式都测过，是界面框架这层更深的窗口限制，不是权限问题。所以验证手段是终端直接调用 bundle 里的可执行文件、用环境变量深链把目标视图摆到位再截图，不要指望点击导航（open -a 传不进环境变量）。
特性开发维护

改代码的几条硬规矩

01
不为向后兼容留旧路径
发现过时的实现路径，直接移除它，而不是加兼容层、回退逻辑或迁移流程去迁就它。
02
一屏一模块、一个外部能力一个适配模块
适配模块目录里必须有一份 README，固定三段：借自哪个项目哪个文件、借了什么、没借什么。
03
存就是为了取
每加一列、每建一张表，都要说得出哪个界面或命令会来取它；说不出就不建。
04
失败如实显示，不假装
没做的功能写「未建」、占位不放模拟数据；替身路径的产出必须自我标注；探不到的工具灰态加一句怎么装，不隐藏也不假装能点。
05
schema 迁移
开发期改了 schema 直接删库重建；从试点起恢复双守卫——每加一列必须同时改 schema 并加迁移守卫，否则存量库直接崩。
06
文档与代码不符，整块重写
不在旁边追加一段「原来是 X，现在是 Y」的补丁——两层叙述并存，读的人下次还得再判一次哪层作数。

文档写到哪

你要写的落在哪
V4 的设计（某个模块怎么设计的、为什么）docs/v4-prototype/design.md —— 唯一设计事实源，一站走完就把那一章改成实况
还没干的活（含缓做的功能与结构债）docs/LEFTOVERS.md —— 唯一清单，不设第二个
怎么用 / 怎么开发就是这份文档
怎么讲给同事听v4-对外宣讲.html
出包与版本号docs/releases.md
新开一批代号先去 docs/code-schemes.md 登记，别撞车

文档整理不跟开发混在一次会话里做：一站还没定型时去扫文档大概率白扫。等用户在真实环境里验证过这一站，另开一个会话专门做。
