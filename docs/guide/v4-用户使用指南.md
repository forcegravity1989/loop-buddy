## 这套东西想让你怎么干活

一个项目分五个阶段,每周转一圈。**你做的事只有两类**:说清楚要什么,以及在关键
路口点头。剩下的——查资料、写代码、写文档、提交、开 MR——交给 agent。

所以整份指南只有一条主线:**接进来 → 每周定目标 → 派活 → agent 干 → 你验收**。

## 第 0 站 · 把一个项目接进来

**这一站已经走过,下面写的都是实际发生的。**

### 你要准备什么

- 一个 git 仓(GitHub 或 codehub 上的都行),你有它的读权限
- 本机装了 `gh`(GitHub)或 `codehub-cli`(内部),并且**登录过**

打开 buddy,项目墙上那条环境条会当场去 PATH 里找这些命令,找得到绿、找不到红。
**红的不影响别的事,只影响对应那条路能不能走**。

### 工作区目录先看一眼

「设置」里有一格「工作区根目录」。以后接进来的项目,仓就 clone 到这个目录下面,
一个项目一个子目录。**默认值在 macOS 上是 `~/.builders-workbench/workspaces`,
Windows 上是用户目录下的同名路径**;要放到别的盘,现在就在这格里改掉、点保存——
改完立刻生效,重启还在,而且**已经接进来的项目不会跟着搬家**(它们的路径当场被
钉死在原处)。

### 接:两步

点「+ 接入项目」。

**第一步只问一件事:这个项目在哪。** 光标点进「项目地址」那格,buddy 就去问平台
要你账号下的仓,列成下拉框;打字即在这批里检索,点一行即选中。不想理列表就直接
把 `owner/repo` 打进去,一样算数。框里右边那个 ⟳ 是重新拉一次。

列不出来的时候会把命令的原话摆给你看(多半是没装或没登录),**不会摆一张假列表**。

**第二步是基础信息**,四格:项目名称、你想做什么、最像的对标、三个月长成什么样。

这一步顶上会先告诉你**这个仓被 buddy 接管过没有**——判据是去它远端读
`.bw/project.toml`:

| 你会看到 | 意思 | 你该做什么 |
|---|---|---|
| 已经被 buddy 接管过 | 同事先接过,或者你以前接过 | 四格是回显出来的,直接改就行;接进来时不会覆盖仓里已有的字 |
| 还没被 buddy 接管过 | 仓在、就是没这份文件 | 四格自己填 |
| 找不到这个仓 | 地址敲错了、私有仓没权限、没登录 | **先把地址改对**,接一个不存在的仓后面每步都会失败 |
| 没查成 | 网不通、默认分支不叫 main | 照样能接;仓里真有名片的话,接入时以仓里的为准 |

最后两行是特意分开的:**「没查成」不等于「没被接管过」**。混成一句的话,你会照着
空格子填一遍,接进去反而把仓里真正的名片盖掉。

### 点「完成接入」之后会发生什么

界面上一步一句地摆出来,做完的那行原地换成结果——**这一下要十几秒,别猛点**:

1. **取仓**——目录里已经是 git 仓就直接用(顺带把它的 origin 报出来给你核对);
   目录不在或是空的就 clone;没填远端就建个空目录并说明它是空的;
   **目录里有东西又不是 git 仓就当场弹回**,既不敢往里 clone,也不敢把别人的
   目录当成这个项目的仓。
2. **库里落一行项目**——只存定位:名字、本机路径、远端地址。名片不进库。
3. **写名片**——`.bw/project.toml`。仓里已经有就一个字不覆盖、只补空着的字段。
4. **自动建一张「规范铺底」的活**——它建一条分支、往仓里写全套规范骨架
   (项目章程、给 agent 的工作约定、`.bw/*`、周计划目录、发版记录)、**提一个 MR**,
   然后**停在评审中等你合**。它不会自动合,也不会自动把活标成完成。
5. **自动进这个项目**。

第 4 步没成不会推翻前面:项目已经接进来了、仓已经在本机了,这两件是真的。回头
在「配置」屏点一次「规范铺底」重来就行——它按标题幂等,重来不会多建一张活。

### 接错了怎么办

**项目卡右上角有个 ✕**。点一下先问一句,再点「移走」才真移走。它只把这个项目从
工作台移出去(项目行、它所有活的账),**仓一个字节都不动**——硬盘上的代码还在
原地,活自己的工作目录也还在。回执里会告诉你仓在哪儿,你真要删自己去删。

### 这一站结束时,你手上有什么

- 本机一个真实的仓(clone 下来的)
- 工作台上一个项目
- 一张停在「评审中」的「规范铺底」活,和它在远端的 MR

**下一步是去合那个 MR。** 合完这个仓就有管理体系的正本了。

## 还没走到的站

下面这些**还没实际走过一遍**,所以这里只留标题,不写步骤——走到哪一站,那一站的
PR 合入之前把它补上来。

- **第 1 站 · 周一看总览**:这项目是什么、健康吗。第一次多半是灰的(没数据 =
  灰,不是绿)。
- **第 2/3 站 · 开始本周**:一次 agent 会话里做完「复盘上周 → 更新指标 → 定本周
  目标和活清单」。
- **第 4 站 · 干活**:每张活按类别选开工工具,agent 在这张活自己的工作目录里干,
  你在内嵌终端里全程看得见、随时能停。
- **第 5 站 · 验收闭环**:提交并开 MR → 评审 → 合入 → **你点完成** → 记发版。
- **第 6 站 · 定时**:资产盘点自动建活并自动开工,停在评审中;下周一回到总览。

## 两条你随时可以拿去核对的规矩

1. **「完成」永远由人点。** agent 干完最远只到「评审中」;定时任务只会自动
   **建**活,绝不自动**完成**活。
2. **没数据就是灰,不是绿。** 健康灯只能从真实数据推出来,界面上任何一个数字都
   能用 `sqlite3` 直接查库核对。
