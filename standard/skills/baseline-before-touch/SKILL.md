# 先测基线再动手 (baseline-before-touch)

## 何时用

优化段动手重构或调性能之前(无基线不动手);以及收尾时报 delta。

## 步骤

1. 动手前先真实测量并落盘:测试数、clippy 警告数、代码行数、构建耗时——全部来自真实命令输出的原样摘录。
2. 每步重构保持测试全绿;一步只做一类等价变换。
3. 删减优先:能删的代码是最好的优化,删除行数计入成果。
4. 结束时用与基线完全相同的命令重测,报 delta;无 delta 也如实报。

## 反例

「感觉快多了」——没有前后同命令对照的数字,这不是优化结论,是错觉。
只优化不删减同样是警报:先找可删的。

## 在 Claude CLI 会话里如何协作

你在一段可见的 Claude 会话里完成本阶段工作,需要多角色时自己调 SubAgent,buddy 不再逐阶段脚本驱动。

**主 Agent 负责什么**:推进基线测量 → 瓶颈定位 → 优化/删减 → 回归验证全链;产出落为 docs/baseline.md、docs/bottlenecks.md、docs/regression.md 和真实代码改动。

**哪些环节调独立 SubAgent**:
- 瓶颈审计:调一个只拿源码路径(不拿你的优化意图)的 SubAgent 做只读审计,产回瓶颈清单(重复逻辑、过度复杂、可删项,每条附文件:行)。它不知道你想优化什么,因此不会被你的意图带偏。

**交接什么产物**:审计 SubAgent 交回 docs/bottlenecks.md(按影响排序,含具体代码位置)。主 Agent 据此做小步重构,每步保持测试全绿。

**何时回用户确认**:瓶颈清单出来后,给用户看一眼排序——先动哪个。优化完报前后 delta,无 delta 也如实报。

**失败或证据不足停哪**:基线命令跑不出真实数字就停下,不估算;优化过程中测试变红立刻停并回退,不带着红测试继续;删减不是乱删——能删的才删,不能删的留。

**完成标准**:docs/regression.md 存在并含与基线完全相同命令的前后对比;测试全绿;有一次 git commit。
